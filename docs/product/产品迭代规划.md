# AI 项目产品迭代规划
标准文件名：AI_PRODUCT_ITERATION_PLAN.md
适用：适配项目四层架构、双AI全自动开发体系、全版本增量迭代
强制绑定：开发主规范、代码稽查规范、API接口规范、四大全局规范
核心机制：分层迭代、增量兼容、无破坏性更新、版本闭环、全自动落地
唯一职责：本文是 V1.0/V2.0/V3.0 产品能力、交付范围和启用边界的唯一可信来源；架构与研发文档只引用，不复制版本能力表。
一、迭代权责与核心定位
1. 体系定位：项目专属串行增量迭代体系，严格适配四层架构，禁止跳迭代、乱迭代、破坏性迭代。
2. 开发AI权责：严格按既定版本范围增量开发，禁止私自修改存量架构、存量逻辑、存量API，禁止超范围开发。
3. 稽查AI权责：逐版本核验迭代合规性、架构一致性、API兼容性、安全性、无技术负债、无破坏性变更。
4. 迭代使命：版本稳步递进、单版可用、单版稳定、全程可回溯、支撑商用交付。
二、迭代强制铁律（全局最高优先级）
1. 架构不动原则：迭代仅增量新增、细节优化，禁止改动四层架构、核心底座、引擎中间件主体结构。
2. API绝对兼容：禁止删除、修改存量接口路由、字段、类型、返回结构，仅允许新增接口、新增字段、新增能力。
3. 串行不跳步：严格遵循 V1.0→V2.0→V3.0 顺序，上一版本未验收闭环，禁止开启下一版本迭代。
4. 模块闭环迭代：单版本内按标准开发层级串行落地，单模块完成开发、自检、稽查、验收后，再推进下一模块。
5. 零技术负债：每版迭代必须合规整洁，无冗余、无硬编码、无隐性BUG，禁止堆积待优化项。
6. 文档同步迭代：功能、接口、配置、逻辑迭代变更后，配套文档同步更新，保证代码与文档100%一致。
7. 版本隔离独立：新旧版本能力相互隔离兼容，新版逻辑不污染旧版存量业务。
8. 迭代范围锁死：单版本迭代范围确定后，禁止私自新增非规划功能、超范围开发。
9. 版本需求冻结：版本迭代启动后，中途禁止临时增改需求，保证迭代稳定可控。
10. 数据库增量规范：数据表变更仅允许增量迁移，禁止直接改表、删字段、改字段类型；迁移操作可回滚、可兼容、可追溯。
11. 配置兼容规范：配置文件仅新增Key，不删除、不修改存量Key，保障旧配置平滑兼容。
12. 依赖版本锁死：依赖包迭代仅微调兼容版本，禁止随意升级大版本，规避环境崩坏、兼容故障。
13. 迭代回滚兜底：迭代出现重大BUG、兼容故障，支持模块级、版本级完整回滚，保障项目稳定。
14. 增量版本兼容：所有开发预留多版本扩展能力，增量迭代，不污染存量代码、不跨版本混用能力。
15. BUG分级闭环：致命BUG立即阻断迭代优先修复，普通BUG版本内清零，无延期遗留BUG。
16. 全局文档同步铁律（唯一执行口径）
  - 全局唯一开发基准：四份终版核心规范为永久开发基准，所有开发无条件对齐，禁止自定义规则。
  - 普通业务新增/逻辑修改：仅更新进度文档、对应模块API文档，不改动四份核心规范。
  - 全局机制、架构底层规则变更：必须同步更新对应核心规范，保证规则、代码、文档完全一致。
  - 核心规范为体系标准，非业务文档，日常业务迭代禁止修改、篡改、扩写规范内容。
三、迭代核心目标
1. V1.0 基础可用版：完成基建、底座、引擎、基础业务、前端基建，搭建全套标准化体系，实现本地可用闭环。
2. V2.0 稳定增强版：优化底层稳定性、完善安全权限、补齐业务能力、优化API体验、适配私有化部署。
3. V3.0 商用成型版：落地多租户隔离、集群高可用、等保合规、SaaS体系，实现云端商用交付。
四、分版本迭代范围
V1.0 基础可用版（项目地基·必稳必净）
1. 项目骨架基建：搭建标准化工程、目录、依赖、配置、工程脚本、基础规范落地
2. 通用平台底座：实现日志、异常处理、数据库适配、全局工具、基础服务入口
3. 核心引擎中间件：封装缓存、队列、事件总线、基础网关，保障底层调度可用
4. 基础业务能力：落地核心业务模块、基础逻辑、能力注册、通用模板
5. 前端基础体系：搭建前端工程、基础UI、插槽扩展、基础业务页面
6. 基础安全能力：实现登录鉴权、基础权限管控、审计日志预留
7. 基础API体系：落地标准化API、统一校验、统一响应、基础文件能力
8. 版本收尾：全维度测试、本地部署适配、零重大BUG、完成初版闭环交付
V2.0 增强稳定版（体验优化·私有化适配）
1. 底座优化：数据库性能优化、日志分级、异常精细化处理、底座稳定性升级
2. 引擎增强：完善队列重试、事件容错、缓存策略、网关精细化调度能力
3. 业务补齐：迭代短板场景、完善边界逻辑、提升业务容错与稳定性
4. 安全完善：分级权限、数据脱敏、越权拦截、全流程操作审计落地
5. API升级：新增批量接口、优化分页性能、完善幂等、限流、超时机制
6. 前端优化：交互体验、状态提示、异常适配、页面兼容性优化
7. 私有化适配：环境隔离、离线部署、私有化配置适配
8. 版本收尾：全量回归、性能优化、问题全闭环、稳定私有化交付
V3.0 商用SaaS版（多租户·集群·合规商用）
1. 多租户架构：实现租户隔离、租户配置、权限隔离、数据与资源隔离
2. 集群高可用：适配集群部署、负载均衡、服务发现、容灾降级
3. 商用安全合规：等保合规适配、加密升级、安全加固、风险防控
4. SaaS前端体系：搭建租户后台、统一控制台、商用SaaS UI体系
5. 高级能力迭代：智能调度、高级队列缓存、分布式事务、高并发适配
6. 商用交付能力：云端部署、镜像交付、自动化运维、监控预留
7. 版本收尾：全场景验收、压力测试、安全测试、正式商用交付
五、迭代通用永久规则
1. 能力递进规则：地基→优化→商用，版本能力只增强、不回撤、不推翻。
2. 全量兼容规则：新版迭代100%兼容旧版数据、接口、业务逻辑。
3. 缺陷清零规则：上版本遗留问题，必须在下版本前期全部清零闭环。
4. 能力沉淀规则：每版迭代完成后，沉淀通用组件、工具、API，持续丰富底座能力。
5. 冷热更新规则：功能优化、参数扩展走热更新；架构、底层、数据表重大变更走冷更新停机迭代。
6. 归档瘦身规则：验收通过模块可归档瘦身；未验收内容完整保留，禁止删减，对齐主规范机制。
六、双AI迭代执行与稽查标准
1. 开发AI执行标准：增量开发、不篡改存量、不超范围、逐任务合规自检、实时回写进度。
2. 稽查AI核验标准：核验迭代兼容性、架构统一性、API规范性、安全稳定性、零技术负债。
3. 迭代固定节点：版本范围确认→模块全自动续跑开发→模块自检→稽查整改闭环→版本全量验收→归档进入下一版本。
七、终极固定执行流程
读取全套规范+当前版本规划 → 核对迭代范围与进度 → 逐模块增量开发+合规自检 → 模块完工稽查整改闭环 → 版本全量测试优化 → 版本验收归档 → 启动下一版本迭代。仅报错、阻塞、需求模糊时询问用户，其余场景全自动迭代推进。
