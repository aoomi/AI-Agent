# AI Agent 已确认产品决策

版本：1.0  
生效日期：2026-08-07  
状态：当前有效  
职责：只记录已经确认的产品定位、用户可见边界和不可回退决定；不复制目录、命名、工程实现或版本能力表。

## 一、产品定位

### PD-001 通用可插拔 AI 基础平台

- 决策：AI Agent 是私有化部署与 SaaS 多租户共用的 AI 应用基础平台，不是只服务短剧的单体系统。
- 用户价值：客户能够按需选择业务能力，并在同一平台上扩展新的行业应用。
- 非目标：不把具体行业流程、模型工作流或生成工具固定写入平台内核。
- 状态：已确认。

### PD-002 短剧是 V1.0 首个业务插件

- 决策：短视频/短剧流水线作为首个官方内置插件交付，不代表平台底座等同于短剧系统。
- 用户价值：V1.0 能形成可用业务闭环，同时验证插件式平台能力。
- 版本范围：具体 V1.0/V2.0/V3.0 能力只引用 `产品迭代规划.md`。
- 状态：已确认。

## 二、部署与客户边界

### PD-003 私有化与 SaaS 共用底座

- 决策：私有化独立部署和 SaaS 多租户共享同一平台架构，通过配置、授权、租户上下文和插件启用范围区分。
- 用户价值：客户能够从本地或私有化部署平滑升级，而不重新建设业务系统。
- 约束：不得为了单一部署形态复制第二套平台核心。
- 状态：已确认。

### PD-004 数据与身份范围不可串用

- 决策：所有项目、用户、租户、会话和插件运行上下文必须具有稳定身份范围；跨项目、跨用户、跨租户默认隔离。
- 用户价值：避免聊天、资产、任务和生成内容串项目或泄露。
- 状态：已确认。

## 三、能力组合与插件规则

### PD-005 业务能力必须可插拔

- 决策：行业流程、生成节点、模型工具和增值能力以插件或标准能力提供方接入；客户只启用已购买或已授权能力。
- 用户价值：按需配置功能，不被固定套餐或无关模块绑架。
- 依赖边界：技术必需依赖、可替代输入依赖和可选增强依赖必须分别声明；缺少可替代插件时允许标准素材导入，不得伪装为流程成功。
- 状态：已确认。

### PD-006 平台能力与业务能力分离

- 平台基础能力：身份、权限、配置、授权、任务、事件、队列、数据访问、模型网关、安全、可观测和插件生命周期。
- 业务插件能力：短剧大纲、剧本、分镜、资产生成、镜头画面、视频、音频、字幕、合片、审核、增强和导出等行业流程。
- 决策：任何业务节点不得因“基础版”名义写入平台底座。
- 状态：已确认。

### PD-007 外部 AI 工具可替换

- 决策：LangGraph 用于可恢复流程编排方向；Dify、ComfyUI 和模型服务作为可替换能力提供方，通过平台适配入口接入。
- 用户价值：更换模型、工作流或工具时不改变用户项目和业务插件契约。
- 约束：前端和业务插件不得直接绑定第三方工具的私有接口。
- 状态：已确认。

## 四、前端与交互边界

### PD-008 保留已确认 UI 视觉和交互

- 决策：旧 Drama Pipeline 已确认的工作台 UI 作为迁移视觉基线；迁移和业务接入不得擅自改变布局、颜色、字号、名称和交互方式。
- 允许变化：为适配新架构进行的内部拆分、契约接入和状态解耦，只要用户可见表现保持一致。
- 状态：已确认。

### PD-009 UI 与业务状态分离

- 决策：前端 UI Store 只管理布局、弹窗、加载、选中和个人偏好；项目、任务、资产和生产状态来自标准业务 Store 与服务端真实状态。
- 用户价值：刷新、切换项目和后台任务恢复时不出现虚假状态或串项目。
- 状态：已确认。

## 五、质量与真实状态

### PD-010 禁止演示成功和伪状态

- 决策：页面只能展示真实服务、真实任务和真实产物状态；禁止用硬编码、模拟数据或客户端伪造“成功”“已归档”“已生成”。
- 验收：接口成功、任务完成、文件存在、页面可见和刷新恢复需要形成完整证据链。
- 状态：已确认。

### PD-011 人工关口不可绕过

- 决策：生成、自动审核、修复和恢复可以后台执行，但已定义的人工确认关口不得被自动续跑、刷新恢复或服务重启绕过。
- 用户价值：用户对内容和成本相关操作保持最终控制。
- 状态：已确认。

### PD-012 最小范围修复与历史保留

- 决策：内容或资产变化只失效受影响范围；优先修复单集、单场景、单镜头、单台词或局部时间窗，旧资产和确认版本保留历史。
- 用户价值：减少重复生产、等待时间和算力成本。
- 状态：已确认。

## 七、决策变更流程

### PD-014 开发与稽查 AI 是可配置 Skill

- 决策：主线开发 AI 与稽查 AI 均以独立内置 Skill 注册，分别保持可写开发权限与只读稽查权限。
- 用户价值：用户可以选择不同模型、调整角色配置，并通过对话完成复杂设置与任务编排。
- 约束：模型选择必须来自平台注册表；稽查 Skill 不得因模型或对话配置获得写权限；未接入真实模型时不得伪造执行成功。
- 状态：已确认。

### PD-015 全行业流程统一为可配置 Skill 机器人

- 决策日期：2026-08-07。
- 决策：平台面向全部行业提供统一流程机器人机制；一个业务流程对应一个独立 Skill 机器人，每个机器人拥有独立身份、上下文、权限、生命周期和模型配置。
- 用户价值：用户能够按行业组合流程机器人，分别选择模型，并通过对话完成复杂流程配置与运行。
- 影响范围：Skill 契约、智能体注册、模型绑定、LangGraph 编排、插件模板、前端配置和行业插件。
- 约束：行业逻辑只进入插件；平台只提供通用注册、配置、编排和运行能力；模型必须来自平台注册表；流程机器人之间只通过契约、事件和授权上下文协作。
- 首个模板：短剧的需求、大纲、剧本、分镜、资产、图片、视频、音频、字幕、合片、审核与导出流程。
- 状态：已确认。

### PD-016 短剧 LoRA 风格由界面配置并确定性匹配

- 决策日期：2026-08-07。
- 决策：LoRA 设置进入短剧“新建项目”和“项目设置”的“视觉风格”区域，展示中文风格名称、自动识别结果、当前模型、权重和锁定状态。
- 默认模式：按短剧类型确定性匹配并锁定项目 LoRA；同一项目和同一资产版本保持一致。
- 可选模式：用户可固定选择、手动覆盖；随机选择只在用户主动启用“风格探索”时生效。
- 风格范围：现代、古风、二次元、古风写实。
- 审计：保存识别类型、LoRA 文件、权重、基础模型、配置版本、修改主体和时间。
- 状态：已确认。

### PD-017 机器人采用上下文驱动的通用对话闭环

- 决策日期：2026-08-07。
- 决策：机器人必须结合当前 Skill、模型配置、项目、任务、历史对话和长期偏好理解用户真实目标；复杂请求形成计划并通过工具或流程执行。
- 交互：信息充分时直接处理；只有缺失信息会实质改变结果时才提出一个必要问题；回复先给结论并使用用户语言。
- 安全：只读操作可直接处理；配置、写入和高风险操作生成可确认、可追溯提案；不得伪造工具调用或执行结果。
- 影响范围：对话服务、记忆、Skill 路由、模型结构化输出、任务执行和机器人配置界面。
- 状态：已确认。

### PD-018 短剧 Skill 采用六类机器人一键启用

- 决策日期：2026-08-07。
- 决策：短剧项目只展示项目策划、编剧、视觉资产、视频制作、后期制作、稽查六类机器人；底层流程 Skill 保持独立。
- 交互：用户点击卡片即可启用或停用，系统自动创建项目隔离机器人、绑定流程并采用自动模型策略。
- 配置：按项目持久化，刷新恢复；未启用对应机器人时禁止启动相关生产任务。
- 状态：已确认。
