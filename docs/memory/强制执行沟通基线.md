# AI Agent 项目强制执行沟通基线

版本：1.0  
生效日期：2026-08-07  
适用范围：`/Users/aoo/Code/AI Agent`

## 一、职责与优先级

1. AI 兼任项目架构师和高级开发工程师，负责识别架构冲突、重复实现、无效耦合和不可交付方案。
2. 当前用户明确指令优先；已确认产品决定以 `docs/product/PRODUCT_DECISIONS.md` 为准，版本能力以 `docs/product/产品迭代规划.md` 为准；架构与工程分别以 `系统架构设计.md` 和 `研发工程统一规范文档.md` 为准。
3. 目录与命名不接受其他文档覆盖，分别只认 `DIRECTORY_README.md` 和 `AI_EXECUTION_NAMING_RULES.md`。
4. 本文只补充本项目规则；通用沟通、安全、授权、文档和交付规则继续引用 `/Users/aoo/Documents/基础开发记忆/通用强制执行沟通基线.md`，不复制第二份。

## 二、固定读取顺序

每次进入项目固定读取：

1. `docs/memory/项目记忆.md`。
2. 本文。
3. 根目录 `README.md`、`AGENTS.md`。
4. 当前任务对应的产品、架构、工程、API、数据库、安全或运维文档。
5. 涉及目录或命名时强制读取对应唯一来源。

## 三、任务执行

1. 用户任务按接收顺序执行；用户明确指定优先级时按指定顺序。
2. 同一主线内的直接阻塞缺陷优先修复，修复后自动返回主线。
3. 未获得明确授权，不把 UI 迁移扩展为业务迁移，不把文档治理扩展为代码重构。
4. 发现规范冲突时先停止受影响部分，列明冲突来源和影响；能够由唯一来源直接裁决的，按唯一来源执行并同步引用。
5. 长任务只在关键节点、风险或阻塞时汇报；普通回复保持简短。

## 四、四层架构强制边界

1. 视图层只包含页面、组件、样式、UI 交互和 UI 临时状态。
2. 跨层字段、事件和类型必须先进入 `shared/contracts/`。
3. 平台底座只包含通用能力，禁止短剧、法律、电商等行业流程进入 `.kernel/` 或 `platform/`。
4. 业务功能必须以插件实现；插件之间通过契约和事件通信，禁止直接跨插件导入。
5. 页面禁止裸请求、接口硬编码、业务计算和业务数据持久化。
6. LangGraph、Dify、ComfyUI 等工具必须经 `platform/adapters/` 接入，不得让业务或 UI 直接绑定第三方实现。

## 五、迁移与删除规则

1. 旧项目只作为迁移来源，禁止整文件覆盖新框架。
2. 迁移只带入当前范围明确允许的内容；旧 API、旧 Store、演示数据、旧环境和兼容债务必须排除。
3. 待删除或替换的文件先按原目录结构迁出到 `/Users/aoo` 下独立备份目录，再从新项目移除。
4. 备份目录必须记录到 `项目记忆.md`，未获用户确认不得永久删除备份。
5. 用户已有代码和未关联修改必须保留，禁止使用破坏性回退命令。

## 六、文档治理

1. 同一规则只能有一个主文档；其他文档使用链接或控制编号引用。
2. 修改文档前完整读取，采用原位融合、去重和冲突检查，禁止尾部机械追加同义内容。
3. 文件名、标题和实际职责必须一致；禁止空占位文件、双 `.md` 后缀和同义主文档并列。
4. 代码或结构变化必须同步项目记忆、变更清单和对应唯一规范。
5. 未验证能力写“待验证”，禁止把规划、骨架或占位描述为已上线。

## 七、验证与交付

1. 代码修改至少执行类型/静态检查、正式构建、关联测试和真实入口验证。
2. 涉及状态和持久化时验证刷新、重开、切换、停止、失败和恢复。
3. 涉及模型、队列或媒体产物时，必须检查真实任务、进程、输出文件、页面显示和持久化证据。
4. 文档修改必须检查路径存在、引用有效、章节唯一和版本同步。
5. 交付状态仅使用：已完成并验证通过、已修改待验证、部分完成、阻塞。

## 八、输出要求

1. 用户要求“完成回复我”时，验证完成后只回复完成结果，不展开无关过程。
2. 存在风险、未完成或阻塞时必须明确说明，禁止用“已完成”掩盖。
3. 所有任务、调整顺序、迁移路径、删除备份和验证结果必须可追溯。
