# 短剧统一生产内核架构规范

版本：1.3  
状态：强制执行

## 阶段完整范围门禁

- 生产阶段完成只能由统一范围门禁从持久台账投影，阶段入口、人工确认、延迟确认、批量同步和重启恢复必须调用同一完成事实判定；禁止发现任意一条confirmed scope后以`trusted`方式提升整个stage。
- image、video、audio、subtitle必须以当前storyboard的权威shot census为期望集合，按`episode:shot`精确覆盖。至少一集全部期望镜头存在且已确认才允许后续阶段启动；缺scope、待确认、非法scope或缺storyboard census一律失败关闭。完整的其他分集可以独立推进，不得被较早残缺分集阻断。
- 四类媒体实际scope必须全部属于storyboard目标集合；门禁必须保留并检查全部实际记录，禁止只返回完整分集交集后忽略多余项。非规范ID、重复/别名碰撞、非shot类型、目标外集或镜头任一存在即失败关闭。
- 四类媒体shot只有在`lifecycle=completed`、顶层`content_fingerprint/audit_batch_id`非空且confirmation内两项与顶层精确一致时才是有效完成事实；缺失、旧代或不一致确认不得推进，该证据特约束不得误伤非媒体stage。
- 门禁选择与确认判定属于统一共享模块；同一规则必须覆盖确认、恢复和正常入口，禁止三处复制后产生不同完成语义。

## 资产批次会话隔离

- 资产清单提取与资产渲染必须分层：清单提取使用`assets`，人物/场景/道具二维基准图、分镜图和辅助生图统一使用`image` stage及image资源；TripoSR/Blender的`asset_3d`任务投影为`assets`但占用3d资源。正式入口映射、资源映射和持久任务Graph投影必须保持一致，任何二维生图running/completed/failed不得改写assets状态。

- 资产批量生图必须按project+session single-flight，并持有独立AbortController与generation token；权威状态读取、清单合并、状态/error变更、缓存清理、每次模型提交前后及持久化边界均验证同一project/session/signal/token。
- 项目切换或停止必须abort并立即隔离旧flight，使旧Promise阻塞时仍可重试；旧成功、异常和finally不得污染或清除新项目/新flight。子级基准图生成必须继承批次signal，取消后禁止提交下一模型。
- 回收旧批次必须按flight/controller/token三重身份原子复位batchGenerating、stage status和旧generating卡片；旧finally只有仍拥有三重身份才可复位。stop须以epoch隔离异步响应，禁止旧stop覆盖新批次状态。
- single-flight公开入口不得声明为async后再返回共享Promise；必须用普通函数直接返回权威flight，保证同一project/session并发调用Promise identity严格相同且底层只创建一批。

## 分镜断点续生成

- storyboard续生成必须把既有shots提交服务端；完整集由服务端按15–23镜、连续镜号、2–9秒单镜、连续时间线和目标总时长共同判定，存在少量镜头不得冒充完成。
- 完整集禁止重复调用模型，并原样保留图片、确认、版本及扩展字段；部分集按整集重生。服务端仅合并本批缺失集并按episode/shot_number排序，重复键、非法编号或provider跨集输出必须失败关闭。
- 前端以启动时existingShots为底，只替换服务端声明的generated_episodes；提交、响应、合并、错误及持久化均服从启动project/session/AbortSignal，旧项目晚到零污染。

## 审核与导出统一阶段门禁

- upscale台账必须物理分离投影与权威字段：`progress_json`只保存completed/total等前端进度；`content_fingerprint`、`audit_batch_id`、`generation`、`production_evidence_json`、`audit_evidence_json`、confirmation及其completed生命周期仅由服务端专用提交/确认方法写入。公开`/api/production/scopes`与`/bulk`必须使用projection方法，忽略客户端携带的权威字段，禁止创建待确认/已确认权威状态；批量replace不得删除服务端代际或已确认scope。请求体中的authority/trusted等元数据永远不能提升权限。
- 每个真实upscale在物理执行前按tenant/user/project/stage/scope以SQLite `BEGIN IMMEDIATE`分配持久单调generation；指纹必须同时绑定generation与服务端batch。权威提交使用revision CAS且只接受当前已预留代：低代、未预留代及旧fingerprint+batch重放全部拒绝。同代权威证据不可变，完全相同值重复提交仅作幂等读取，不递增revision或撤销confirmation；任一证据差异失败关闭。跨实例并发只允许最新代提交，重载后约束不回退。
- 人工确认与enhanced导出必须同时精确绑定`content_fingerprint + audit_batch_id + generation`；旧页面确认声明缺任一项或不匹配当前代必须拒绝。enhanced authority只读取服务端独立证据列并覆盖客户端声明，manifest逐集携带source_version/fingerprint/batch/generation/production/audit evidence。`legacy_base_scope`缺省证据只适用于base历史composition，enhanced缺证必须失败关闭。

- production_evidence必须保留原始JSON结构，不得字符串降格；空对象/数组/字符串、不可JSON序列化对象及NaN/Infinity均失败关闭。fingerprint规范化必须递归排序全部对象键并禁止非有限数，嵌套键序变化稳定、语义值变化敏感。
- 资产统一FIFO必须以key→owner token和epoch隔离：重复key不得重复执行；停止/项目切换后新owner可立即取得同key，旧任务finally仅能删除自身owner，禁止清除新owner。顺序、owner与代际必须用正式函数动态测试，不得只做源码存在性断言。

- 成片增强必须作为`review_export/upscale`服务端批次执行：前端一次操作严格一次runStage，不得逐集直调超分、字幕OCR、人脸审核或终审接口。服务端按集串行执行并贯穿同一lease/cancel checkpoint；任一真实审核失败立即终止后续，保留诊断并写failed，禁止自动把失败母版伪标skipped。
- 增强批次必须先全量验证再执行：每条command必须为对象，episode为唯一正整数，source为合法绝对媒体路径/URL，source_version与目标width/height/fps/mode完整合法；任一非法时整批ValueError，超分与全部审核provider调用数必须为零。
- 增强成功证据必须由服务端生成：content_fingerprint绑定source media/version、增强输出、target、production evidence和真实audit evidence；audit_batch_id同批稳定、跨批不同。只有整批成功且取消检查通过后才能原子写`review_export/upscale:{episode}` pending_confirmation，人工确认后转completed；失败或取消禁止写成功证据。enhanced导出只接受当前已确认fingerprint/batch，客户端自报、篡改与旧批次均拒绝。
- fingerprint必须覆盖完整规范化command、完整增强输出及所有步骤证据，不得只选择部分字段。OCR、face、final证据结构固定为status+evidence；未启用步骤必须为not_applicable并给出原因，启用且pass但无真实evidence必须失败关闭。JSON键顺序不影响指纹；字幕、引用、过程审核、合规状态或任一步evidence变化必须改变指纹。
- 前端增强入口必须捕获启动project/session/AbortController，只原子接收服务端items；项目切换主动abort，晚到成功/异常不得改写当前项目。价格试算可作为无副作用预检保留，但不得创建生产状态。
- 报价预检、用户确认与正式增强提交属于同一single-flight事务；公开入口必须是非async函数并直接返回权威Promise。同project/session重复点击只允许一次quote、一次confirm、一次runStage。项目切换/stop必须释放旧flight并递增epoch，忽略signal的旧响应与旧finally不得污染或清除新任务；拒绝、取消、异常后必须释放以便重试。

- 最终审核与导出必须由服务端`review_export`阶段执行器承载，前端不得直连审核或导出能力；两种操作共享同一stage lease、取消事件、心跳与租户边界。
- 审核按唯一分集命令串行提交，必须保留真实`status/issues/evidence`；取消或失租后禁止提交下一集。
- 一次用户审核操作必须一次性提交全部目标分集，严格对应一次服务端阶段调用；禁止前端按分集或修复次数循环创建阶段。服务端逐集执行，瞬态失败最多重试一次，并返回完整分集诊断；业务审核不通过不得通过重复调用伪装成功。
- 导出是审核之后的独立操作。启用审核时，每个待导出集必须有已人工确认的真实通过记录；缺失、失败或仅自动通过未确认均应拒绝，禁止生成交付清单。
- 请求体中的审核状态、确认标记、指纹和批次仅是声明，不是授权事实。导出服务端必须按tenant/user/project读取统一生产台账，逐集验证review scope与实际composition/upscale媒体scope均为completed，confirmation存在且其content_fingerprint/audit_batch_id与台账及当前声明一致；跨租户项目、旧版本、未确认或伪造声明必须在调用导出提供方前失败关闭。只有显式`audit_required=false`可跳过审核门禁。
- `audit_required=false`只能跳过review审核证据，媒体权威门禁始终执行。source_version枚举固定为base/enhanced：base仅匹配已确认composition scope，enhanced仅匹配已确认upscale scope；禁止任意合并、交叉匹配或静默回落。批量导出任一集缺证必须整批失败且不调用导出提供方。
- 导出入口必须按项目single-flight：同项目重复提交返回同一在途Promise，禁止创建第二阶段调用。请求必须持有AbortController和启动project/session；提交、响应、状态/文件/manifest替换及持久化边界均须校验会话。项目切换或停止立即abort，旧项目晚到成功与异常不得污染当前项目；finally只能释放自身单飞键。
- 停止导出必须同时本地abort与服务端定向取消`review_export` stage，携带完整tenant/user/project；服务端未确认取消必须明确失败。停止应递增生成epoch并立即释放旧单飞键，使旧Promise不响应signal时仍可新建重试；旧Promise晚到和finally只能作用于自身身份，禁止清除新flight。
- 审核/导出仍只依赖`audit.video.final`与`export.package`能力名，提供方可插拔；阶段执行器不得绑定具体模型或存储实现。

## 生产能力并发与插拔门禁

- 每个可替换能力提供方可声明正整数`max_concurrency`；内核必须维护真实`inflight`，只向仍有容量且健康、启用的提供方派发。
- 同优先级提供方必须在并发任务间分流；全部提供方满载时返回明确容量背压，禁止越过容量继续提交或伪造排队成功。
- 提供方存在在途调用时禁止卸载、全量替换或同ID替换；任务释放后方可插拔。停用仅阻止新调用，不得破坏在途调用。
- 运行快照至少包含能力、provider、启用、健康、优先级、`inflight`和`max_concurrency`，作为调度、监控和审计事实。

## 1. 唯一生产内核

- 全链路固定为：需求 → 大纲 → 剧本 → 分镜 → 资产 → 图片 → 视频 → 音频 → 字幕 → 合片 → 审核与导出。
- LangGraph 是唯一服务端编排器；前端只提交命令、显示状态和执行人工确认，不编排生产步骤。
- SQLite 检查点、生产台账、故事事实库和统一任务仓库是服务端事实来源；JSON 仅作兼容投影，不得覆盖权威状态。
- 旧流水线兼容层只能读取LangGraph的`current_stage/next_stage/status`并执行其返回的单一节点；JSON中的索引和状态只能由图状态派生，禁止用于循环、恢复或推进。
- 暂停、取消和失败同样必须先写LangGraph权威状态；取消后重启仍为`cancelled`，禁止批准、恢复或再次执行原流程。
- 大纲、剧本、分镜、图片和视频的拆批、顺序、有限重试、终审、修复和媒体包组合全部由服务端阶段执行器负责；前端每次只提交一个阶段命令。
- 每个节点必须登记真实任务 UUID、输入版本、输出版本、依赖、提供方、心跳、资源占用、错误与人工确认。
- 生命周期统一为 `idle/queued/running/waiting_memory/pending_confirmation/completed/failed/paused/cancelled/stale`，禁止子系统自定义同义状态。

## 2. 可插拔边界

- 最小不可插拔底座仅包含：身份与租户上下文、契约校验、事件、任务生命周期、持久化接口、能力注册表、安全与资源预算。
- LangGraph 节点只依赖能力名，不得依赖模型名、文件路径、ComfyUI 节点或厂商 API。
- 文本、图片、视频、音频、字幕、3D、审核、修复、超分、导出均是可注册能力；提供方必须支持查询、启停、替换和卸载。
- 内置实现与第三方插件使用同一注册协议；禁用或缺失能力必须明确失败，禁止模拟成功或降级成假审核。
- 模型、工作流和运行参数属于提供方元数据；业务产物必须记录本次实际绑定，禁止只记录默认配置。
- 同一能力允许同时注册多个本地、远程或插件提供方；每个提供方必须具有独立ID、优先级、启停状态、健康状态和元数据。LangGraph只引用能力名，禁止把首选模型写死在节点中。
- 同优先级健康提供方采用确定性轮转；显式指定provider时禁止改路由。普通有副作用任务默认不自动故障转移，只有调用方明确声明`allow_fallback`且操作满足幂等/安全重试条件时，才可按优先级尝试后备提供方。
- 内置提供方刷新只能替换自身provider ID，禁止删除或覆盖同能力下的插件提供方；禁用、摘除健康或卸载必须支持provider粒度和整个能力粒度。
- 能力管理与健康接口必须披露每条绑定的provider_id、priority、enabled、healthy和metadata，不得把多提供方折叠成一个默认实现。
- 存储、任务仓库、检查点、资源调度器和阶段执行器同样属于扩展点，必须具备稳定接口、提供方标识、查询、替换、启停和卸载能力。
- 同一基础设施扩展点允许安装多个提供方，但只能有一个活动绑定；安装不等于启用。切换必须显式激活，可回滚到仍安装且启用的旧提供方；卸载必须精确到提供方，禁止删除同点其他实现。
- `hot_swappable=false`的有状态实现不得替换运行中实例；正式切换顺序固定为停止准入、排空任务、数据迁移、切换绑定、重启服务、恢复校验，失败则回滚旧绑定。
- 不可热替换的有状态扩展必须声明 `hot_swappable=false`，替换后通过受控重启生效；禁止运行中迁移导致任务或台账分裂。
- 每个基础设施提供方必须声明contract_version与required_methods；注册表在实例创建后、交付调用方前强制验证全部方法可调用。契约不完整的PostgreSQL/Redis/远程实现必须立即拒绝，禁止以“已安装”冒充可生产。
- 最小底座不得包含 Ollama、MLX、ComfyUI、FFmpeg、TripoSR、Blender 或具体 SQLite 文件路径；这些只能由扩展提供方注入。

## 3. 统一任务与资源调度

- 文本、图片、视频、音频、3D 共用统一持久任务仓库；各兼容 JSON 文件不得成为权威来源。
- 任务状态写入顺序固定为`统一任务仓库权威提交 → JSON兼容投影`。投影失败不得回滚已提交任务，重载必须由权威仓库覆盖旧投影；权威提交失败时禁止更新JSON。禁止采用JSON先写、SQLite后写的崩溃窗口。
- 同一次store保存涉及多个任务时必须在一个数据库事务中整批提交；第N条失败必须整批回滚。任务提交与LangGraph投影之间使用同事务持久outbox：图投影失败不得向生成业务抛出或改写任务终态，必须由服务启动与后台心跳重放，成功后才确认删除outbox。
- outbox必须具有SQLite生成的全局单调事件revision；确认使用job_id+revision CAS。LangGraph按stage持久最新projection revision并拒绝旧版本，确保两个drain交错时旧事件既不能删除新事件，也不能覆盖新图状态。shutdown期间未确认事件保留到重启重放。
- 多实例投影同一tenant/user/project/stage前必须取得可过期、可自动续租的跨进程持久租约；持锁后重新读取最新outbox再report。进程内锁不得冒充多实例互斥，崩溃后租约必须自动过期并允许其他实例重放。
- 租约句柄必须暴露失租状态；续租异常、owner变化或TTL过期均视为失租。Graph report前后与outbox ack前必须验证所有权；report期间失租必须从权威任务重建更高revision outbox事件，确保新持有者可把图修复到最新状态。并发抢锁的SQLite busy只表示未取得租约，不得终止worker心跳线程。
- 租约owner删除是best-effort并由TTL兜底；单个任务库发生瞬时busy只允许跳过本轮并保留outbox，不得阻断其他任务库重放或杀死心跳线程。
- 所有任务共用可插拔资源调度器；Mac 始终保留至少35GB。文本、审核、图片、视频、3D和超分归入`accelerator`池且同一时刻只运行一个；CPU音频归入`cpu-media`池并允许有限并发；控制、状态和确认归入`control`池，不得被长时间GPU任务阻塞。
- 停止、超时、关闭、看门狗和恢复共用同一生命周期实现；必须精确终止所属进程树或模型 prompt，禁止跨任务误杀。
- 视频终态与owned Comfy prompt执行原子核销：终态提交前后均确认prompt不在running/pending queue；未确认时保持`cancel_pending`并占用原资源票据，不得返回停止成功或释放通道。看门狗发现终态仍有owned prompt时必须恢复票据，核销后再还原原终态。
- 恢复必须重放持久化的原始请求；没有完整请求、依赖或提供方时保持失败，禁止伪造恢复成功。
- 统一任务仓库记录合并到分类任务视图时，历史payload缺失的job ID、租户身份、stage、status、进程和时间字段必须由仓库权威列补齐；启动恢复与watchdog必须覆盖“统一仓库非终态但分类记录缺失/残缺且无实际进程”的任务，并通过正常持久保存、outbox和Graph投影收敛，禁止直接改库或仅清内存状态。
- H3 Ref2VA的Context IR是同一视频任务内的独立串行子阶段：先持久化`h3_context_ir`阶段、独立prompt ID、心跳和三类输出文件，再确认32B Context模型完全卸载并释放Comfy，最后才允许提交H3。优化、持久化、取消、超时或卸载任一失败时H3提交次数必须为0；停止、恢复、看门狗和关闭必须核销当前子阶段prompt。

## 3.1 负载均衡与高并发

- API 层必须无状态化并支持多实例；任何实例不得依赖本机内存判断权威任务状态，权威状态只来自统一任务仓库、生产台账和分布式租约。
- 同一tenant/user/project/stage的正式执行必须取得稳定stage key的分布式租约；generation由持久序列表单调递增。跨实例取消写入该租约的cancel_requested，owner续租失败或看到取消后禁止项目写回和LangGraph完成提交。
- 服务端stage executor必须统一复用该租约的cancel event作为唯一取消事实；requirements至review_export的阶段入口、每个批次/command/poll、本地或远端子调用、审核、修复和fallback前后均设置检查点。取消命中后禁止提交新模型、新command、pending_confirmation或项目晚到写回。
- 正式stop必须携带完整tenant/user/project，先对精确stage key请求取消，再按同一身份精确停止当前文本、图片、视频或3D子任务；缺少身份直接拒绝，禁止按project ID或job ID跨租户停止。
- 阶段最终业务写回必须在租约仓库commit guard内完成：事务开始时复核owner/generation/expiry/cancel，成功提交时消费租约。跨实例取消与最终提交必须线性化，禁止出现Graph cancelled但旧结果先写waiting_confirmation/failed的双事实。
- 服务端权威业务证据禁止在物理执行函数内直接发布；执行器只能返回延迟commit payload。最终提交器必须在同一owner+generation lease commit guard内发布项目写回、权威ledger和Graph。涉及独立SQLite台账时，Graph callback必须位于权威批次事务提交前，callback异常整批回滚；Graph事件须保存可重放核对的scope/generation/fingerprint/batch tuple，重启发现Graph pending而ledger缺项时按原stage generation失败关闭，禁止形成悬空待确认或成功证据/取消双事实。
- LangGraph阶段状态必须保存stage_generation并拒绝较低代事件。旧owner因TTL、续租异常或接管而纯失租时不得提交failed/cancelled；仅能由持久cancel_requested证明的当前代显式取消写cancelled。
- 阶段生命周期、projection revision、stage generation与对应事件payload必须共享同一接受围栏；generation是第一所有权围栏，revision只在同generation内单调比较，更高generation必须建立独立revision序列，不得被旧代较大revision阻断。被拒绝的同代旧revision、旧generation或无代际回调不得覆盖持久事件快照、重启恢复依据或导演决策输入。内核必须保留最近一次已接受事件及按stage权威事件；已有正stage generation后，缺失/零generation按旧代失败关闭。
- 新generation允许以revision 0建立且仅建立一次基线；该stage已有accepted event后，同generation所有事件都必须满足`incoming_revision > current_revision`，缺失revision按0处理且不得重复通过。真正不含按stage accepted event的旧checkpoint允许当前owner首个事件完成一次兼容迁移，迁移后立即进入严格单调；开始、成功、失败、确认和恢复调用方必须显式推进revision。
- 服务监听地址、端口、工作节点ID和服务范围必须由部署环境注入，禁止多实例因硬编码端口互斥。
- 轻量查询、上传、状态轮询和人工确认允许并发；文本、图片、视频、3D等重负载按资源池独立排队，每个物理工作节点仍执行自身内存预算和单重负载限制。
- 节点内调度必须支持`资源类别→资源池`映射、每池独立容量、每池队列上限、池内优先级、超时和按任务取消。默认Mac策略为`accelerator=1/队列16`、`cpu-media=2/队列64`、`control=8/队列256`；超过队列上限立即返回明确背压，禁止创建无界线程。
- 兼容健康快照必须同时提供旧`active`字段和完整`active_items`、`pools`字段；工作节点上报的active必须取实际活动票据数，capacity必须取各池容量总和，禁止继续硬编码容量1。
- 调度器必须按能力、资源类别、可用内存、活动任务数、队列深度、心跳和服务范围选择工作节点；不得把不兼容模型任务路由到错误节点。
- worker路由与远端提交之间必须取得跨实例原子dispatch reservation；预留核算`active + reserved`容量和`available_memory - reserved_memory`，使用request ID幂等、TTL回收及worker generation围栏。全部节点满载时立即背压，禁止多个网关依赖同一旧心跳重复超额派发。
- 正式远端请求边界必须直接消费共享worker registry的reservation结果，禁止先走进程内router再补记预留；成功、远端业务错误、网关错误和连接异常均在`finally`精确释放。重试必须复用显式request/job ID，缺失时使用规范化路径与请求体哈希生成稳定ID。
- 每个任务必须使用服务端UUID、幂等键和带过期时间的所有权租约；只有租约持有者可续心跳、写非终态、终止进程或提交完成结果。
- 物理执行前与权威结果提交前必须分别复核租约owner和generation；执行中失租的旧执行者不得提交任何晚到结果。
- 工作节点失联后租约到期，任务进入`stale`并由看门狗重新排队；旧节点晚到结果必须被任务世代号和终态CAS拒绝。
- 发现仓库和进程内路由视图必须同时按心跳超时清退节点；仅在接口中标记`healthy=false`但永久保留旧节点不合格，禁止僵尸节点污染容量统计与管理界面。
- 必须设置全局、租户、项目和资源池队列上限；超限返回明确背压和可重试时间，禁止无限接收导致内存、文件描述符或线程耗尽。
- 默认本机分层排队上限固定为：`accelerator`全局16/租户8/项目4，`cpu-media`全局64/租户32/项目16，`control`全局256/租户128/项目64。三层校验与入队必须在同一锁内完成；某一项目超限不得阻断其他项目或租户使用其剩余配额。
- HTTP线程、后台执行线程、排队恢复线程和服务重启恢复线程都必须显式携带完整tenant/user/project身份进入资源票据；禁止依赖不会跨线程继承的thread-local作为异步任务唯一身份来源。
- `waiting_memory`属于任务执行子状态，在统一任务仓库中原样保存；投影到LangGraph阶段状态时统一映射为`queued`，不得提交图不支持的子状态或丢失任务真实状态。
- 默认本机提供方使用SQLite租约和单节点路由；横向扩容时必须替换为支持原子租约的PostgreSQL/Redis提供方，业务流程代码不得修改。
- 负载均衡器、任务仓库、租约仓库和工作节点发现均属于可插拔基础设施，当前绑定和健康状态必须可查询。
- 标准执行顺序固定为`能力解析 → 健康节点路由 → 原子租约/世代 → 节点内优先级队列 → 物理执行 → 权威结果提交 → 释放租约`；任何具体模型入口不得绕过。
- API网关选中远端工作节点后必须通过受控数据面转发原始命令，并携带防循环调度标头；目标节点才可取得执行租约。响应必须披露实际执行节点，远端不可达返回503，禁止回落到错误节点本地执行。
- 本机提供方必须实现自动续租、旧世代拒绝续租/释放、节点心跳、资源类型与内存门禁、队列深度背压；管理接口必须同时返回工作节点和节点内资源快照。
- SQLite只用于单机/开发部署，不得由多主机共享文件；多实例正式部署必须安装PostgreSQL任务/台账/检查点提供方和Redis租约/队列/节点发现提供方后才可声明横向高可用。
- 服务关闭阶段只允许停止、失败化、释放租约和注销节点；禁止触发全局导演、审核或任何模型推理。

## 4. 结构化生产约束

- 故事事实库保存角色、姓名、身份、关系、能力阶段、不可逆事件、标题、核心事件和时间线；后续节点只能引用，不得静默改写。
- 资产采用不可变版本；基准资产变更后，所有引用旧版本的图片、视频、音频、字幕、合片和审核记录自动标记 `stale`。
- 每个节点只在全部前置依赖为 `completed` 后运行；输出一律进入 `pending_confirmation`，人工确认后才推进下一节点。
- 人工确认必须先通过LangGraph前序和确认数据校验，再提交生产台账与图检查点；后续提交失败必须补偿回滚台账，禁止留下单边`completed`。
- 审核必须返回真实证据、模型/算法、阈值和失败项；能力未安装时返回 `unavailable` 并阻断生产。

## 5. 三次复用强制规则

- 同一界面结构、交互、状态展示或操作组出现 3 次及以上，必须抽成统一 Vue 组件。
- 同一校验、状态转换、停止、恢复、持久化、路由或错误归一化逻辑出现 3 次及以上，必须抽成共享模块或服务。
- 组件允许通过属性、插槽和事件表达差异，禁止复制组件后仅修改名称。
- 共享模块必须有独立正常、异常和边界测试；调用方测试只验证映射，不重复测试内部实现。
- 代码评审必须搜索同构重复；发现第三处时，本次增量必须同时收口既有两处。

## 6. 验收门禁

- 前端不存在生产编排循环；后端不存在绕过 LangGraph 的跨阶段自动推进。
- 生产能力与基础设施扩展点必须能在管理界面查询全部已安装提供方、活动提供方和启用状态；缺少活动绑定时明确阻断。
- 正式生产路径不存在直接调用具体图片模型实现，必须经能力注册表解析。
- 任务中心显示真实服务端 UUID 与真实进程/心跳状态。
- 未安装审核器不会返回 `pass`；失败、停止、超时和 stale 不会被完成结果覆盖。
- 三类及以上重复资产卡、条目操作、颜色预设、停止/恢复和持久化逻辑均使用统一组件或模块。
- 多实例测试必须覆盖并发幂等提交、租约抢占、租约过期、节点失联、晚到结果、租户限流、背压和不同资源池并行；单机测试继续强制同一时刻仅一个重负载任务。
- 合片前必须逐镜验证video/audio/subtitle三元证据使用同一媒体包审核批次；只比较镜头ID或字段非空一律不合格。
### 阶段进度事件

- 阶段状态以服务端持久revision为事件游标；客户端订阅必须携带最后已处理revision，响应只返回更高revision，超时无变化返回`changed=false`。
- 状态写入、revision递增和等待者通知必须位于同一事务锁，禁止固定高频轮询及“先查后等”丢事件；客户端断线后从最后revision恢复。
- 订阅必须支持项目/租户/用户隔离、取消信号、等待超时和并发槽背压；订阅等待不得占用生产资源池，超限明确429，禁止无限创建线程。
### 中断与重启恢复

- 服务端是恢复唯一执行方：重启时按真实任务/进程和LangGraph状态决定继续或失败化，并同步项目阶段、台账、revision与错误证据。
- 前端加载只读取持久事实并显示“继续”入口，禁止因`generating/running`旧记录自动重新提交任何重负载阶段；新任务必须来自用户显式操作或服务端持久恢复器。
- 同一中断状态的恢复展示必须通过统一处理器，覆盖文本、资产、图片、视频、合片、审核、超分和导出；禁止每个页面各自定时重试。
