# 短剧统一生产内核架构规范

版本：1.3  
状态：强制执行

## 1. 唯一生产内核

- 全链路固定为：需求 → 大纲 → 剧本 → 分镜 → 资产 → 图片 → 视频 → 音频 → 字幕 → 合片 → 审核与导出。
- LangGraph 是唯一服务端编排器；前端只提交命令、显示状态和执行人工确认，不编排生产步骤。
- SQLite 检查点、生产台账、故事事实库和统一任务仓库是服务端事实来源；JSON 仅作兼容投影，不得覆盖权威状态。
- 旧流水线兼容层只能读取LangGraph的`current_stage/next_stage/status`并执行其返回的单一节点；JSON中的索引和状态只能由图状态派生，禁止用于循环、恢复或推进。
- 暂停、取消和失败同样必须先写LangGraph权威状态；取消后重启仍为`cancelled`，禁止批准、恢复或再次执行原流程。
- 大纲、剧本、分镜、图片和视频的拆批、顺序、有限重试、终审、修复和媒体包组合全部由服务端阶段执行器负责；前端每次只提交一个阶段命令。
- 每个节点必须登记真实任务 UUID、输入版本、输出版本、依赖、提供方、心跳、资源占用、错误与人工确认。
- 生命周期统一为 `idle/queued/running/waiting_memory/pending_confirmation/completed/failed/paused/cancelled/stale`，禁止子系统自定义同义状态。

## 2. 可插拔边界

- 最小不可插拔底座仅包含：身份与租户上下文、契约校验、事件、任务生命周期、持久化接口、能力注册表、安全与资源预算。
- LangGraph 节点只依赖能力名，不得依赖模型名、文件路径、ComfyUI 节点或厂商 API。
- 文本、图片、视频、音频、字幕、3D、审核、修复、超分、导出均是可注册能力；提供方必须支持查询、启停、替换和卸载。
- 内置实现与第三方插件使用同一注册协议；禁用或缺失能力必须明确失败，禁止模拟成功或降级成假审核。
- 模型、工作流和运行参数属于提供方元数据；业务产物必须记录本次实际绑定，禁止只记录默认配置。
- 同一能力允许同时注册多个本地、远程或插件提供方；每个提供方必须具有独立ID、优先级、启停状态、健康状态和元数据。LangGraph只引用能力名，禁止把首选模型写死在节点中。
- 同优先级健康提供方采用确定性轮转；显式指定provider时禁止改路由。普通有副作用任务默认不自动故障转移，只有调用方明确声明`allow_fallback`且操作满足幂等/安全重试条件时，才可按优先级尝试后备提供方。
- 内置提供方刷新只能替换自身provider ID，禁止删除或覆盖同能力下的插件提供方；禁用、摘除健康或卸载必须支持provider粒度和整个能力粒度。
- 能力管理与健康接口必须披露每条绑定的provider_id、priority、enabled、healthy和metadata，不得把多提供方折叠成一个默认实现。
- 存储、任务仓库、检查点、资源调度器和阶段执行器同样属于扩展点，必须具备稳定接口、提供方标识、查询、替换、启停和卸载能力。
- 同一基础设施扩展点允许安装多个提供方，但只能有一个活动绑定；安装不等于启用。切换必须显式激活，可回滚到仍安装且启用的旧提供方；卸载必须精确到提供方，禁止删除同点其他实现。
- `hot_swappable=false`的有状态实现不得替换运行中实例；正式切换顺序固定为停止准入、排空任务、数据迁移、切换绑定、重启服务、恢复校验，失败则回滚旧绑定。
- 不可热替换的有状态扩展必须声明 `hot_swappable=false`，替换后通过受控重启生效；禁止运行中迁移导致任务或台账分裂。
- 最小底座不得包含 Ollama、MLX、ComfyUI、FFmpeg、TripoSR、Blender 或具体 SQLite 文件路径；这些只能由扩展提供方注入。

## 3. 统一任务与资源调度

- 文本、图片、视频、音频、3D 共用统一持久任务仓库；各兼容 JSON 文件不得成为权威来源。
- 任务状态写入顺序固定为`统一任务仓库权威提交 → JSON兼容投影`。投影失败不得回滚已提交任务，重载必须由权威仓库覆盖旧投影；权威提交失败时禁止更新JSON。禁止采用JSON先写、SQLite后写的崩溃窗口。
- 同一次store保存涉及多个任务时必须在一个数据库事务中整批提交；第N条失败必须整批回滚。任务提交与LangGraph投影之间使用同事务持久outbox：图投影失败不得向生成业务抛出或改写任务终态，必须由服务启动与后台心跳重放，成功后才确认删除outbox。
- outbox必须具有SQLite生成的全局单调事件revision；确认使用job_id+revision CAS。LangGraph按stage持久最新projection revision并拒绝旧版本，确保两个drain交错时旧事件既不能删除新事件，也不能覆盖新图状态。shutdown期间未确认事件保留到重启重放。
- 多实例投影同一tenant/user/project/stage前必须取得可过期、可自动续租的跨进程持久租约；持锁后重新读取最新outbox再report。进程内锁不得冒充多实例互斥，崩溃后租约必须自动过期并允许其他实例重放。
- 租约句柄必须暴露失租状态；续租异常、owner变化或TTL过期均视为失租。Graph report前后与outbox ack前必须验证所有权；report期间失租必须从权威任务重建更高revision outbox事件，确保新持有者可把图修复到最新状态。并发抢锁的SQLite busy只表示未取得租约，不得终止worker心跳线程。
- 租约owner删除是best-effort并由TTL兜底；单个任务库发生瞬时busy只允许跳过本轮并保留outbox，不得阻断其他任务库重放或杀死心跳线程。
- 所有任务共用可插拔资源调度器；Mac 始终保留至少35GB。文本、审核、图片、视频、3D和超分归入`accelerator`池且同一时刻只运行一个；CPU音频归入`cpu-media`池并允许有限并发；控制、状态和确认归入`control`池，不得被长时间GPU任务阻塞。
- 停止、超时、关闭、看门狗和恢复共用同一生命周期实现；必须精确终止所属进程树或模型 prompt，禁止跨任务误杀。
- 恢复必须重放持久化的原始请求；没有完整请求、依赖或提供方时保持失败，禁止伪造恢复成功。

## 3.1 负载均衡与高并发

- API 层必须无状态化并支持多实例；任何实例不得依赖本机内存判断权威任务状态，权威状态只来自统一任务仓库、生产台账和分布式租约。
- 服务监听地址、端口、工作节点ID和服务范围必须由部署环境注入，禁止多实例因硬编码端口互斥。
- 轻量查询、上传、状态轮询和人工确认允许并发；文本、图片、视频、3D等重负载按资源池独立排队，每个物理工作节点仍执行自身内存预算和单重负载限制。
- 节点内调度必须支持`资源类别→资源池`映射、每池独立容量、每池队列上限、池内优先级、超时和按任务取消。默认Mac策略为`accelerator=1/队列16`、`cpu-media=2/队列64`、`control=8/队列256`；超过队列上限立即返回明确背压，禁止创建无界线程。
- 兼容健康快照必须同时提供旧`active`字段和完整`active_items`、`pools`字段；工作节点上报的active必须取实际活动票据数，capacity必须取各池容量总和，禁止继续硬编码容量1。
- 调度器必须按能力、资源类别、可用内存、活动任务数、队列深度、心跳和服务范围选择工作节点；不得把不兼容模型任务路由到错误节点。
- 每个任务必须使用服务端UUID、幂等键和带过期时间的所有权租约；只有租约持有者可续心跳、写非终态、终止进程或提交完成结果。
- 物理执行前与权威结果提交前必须分别复核租约owner和generation；执行中失租的旧执行者不得提交任何晚到结果。
- 工作节点失联后租约到期，任务进入`stale`并由看门狗重新排队；旧节点晚到结果必须被任务世代号和终态CAS拒绝。
- 发现仓库和进程内路由视图必须同时按心跳超时清退节点；仅在接口中标记`healthy=false`但永久保留旧节点不合格，禁止僵尸节点污染容量统计与管理界面。
- 必须设置全局、租户、项目和资源池队列上限；超限返回明确背压和可重试时间，禁止无限接收导致内存、文件描述符或线程耗尽。
- 默认本机分层排队上限固定为：`accelerator`全局16/租户8/项目4，`cpu-media`全局64/租户32/项目16，`control`全局256/租户128/项目64。三层校验与入队必须在同一锁内完成；某一项目超限不得阻断其他项目或租户使用其剩余配额。
- HTTP线程、后台执行线程、排队恢复线程和服务重启恢复线程都必须显式携带完整tenant/user/project身份进入资源票据；禁止依赖不会跨线程继承的thread-local作为异步任务唯一身份来源。
- `waiting_memory`属于任务执行子状态，在统一任务仓库中原样保存；投影到LangGraph阶段状态时统一映射为`queued`，不得提交图不支持的子状态或丢失任务真实状态。
- 默认本机提供方使用SQLite租约和单节点路由；横向扩容时必须替换为支持原子租约的PostgreSQL/Redis提供方，业务流程代码不得修改。
- 负载均衡器、任务仓库、租约仓库和工作节点发现均属于可插拔基础设施，当前绑定和健康状态必须可查询。
- 标准执行顺序固定为`能力解析 → 健康节点路由 → 原子租约/世代 → 节点内优先级队列 → 物理执行 → 权威结果提交 → 释放租约`；任何具体模型入口不得绕过。
- API网关选中远端工作节点后必须通过受控数据面转发原始命令，并携带防循环调度标头；目标节点才可取得执行租约。响应必须披露实际执行节点，远端不可达返回503，禁止回落到错误节点本地执行。
- 本机提供方必须实现自动续租、旧世代拒绝续租/释放、节点心跳、资源类型与内存门禁、队列深度背压；管理接口必须同时返回工作节点和节点内资源快照。
- SQLite只用于单机/开发部署，不得由多主机共享文件；多实例正式部署必须安装PostgreSQL任务/台账/检查点提供方和Redis租约/队列/节点发现提供方后才可声明横向高可用。
- 服务关闭阶段只允许停止、失败化、释放租约和注销节点；禁止触发全局导演、审核或任何模型推理。

## 4. 结构化生产约束

- 故事事实库保存角色、姓名、身份、关系、能力阶段、不可逆事件、标题、核心事件和时间线；后续节点只能引用，不得静默改写。
- 资产采用不可变版本；基准资产变更后，所有引用旧版本的图片、视频、音频、字幕、合片和审核记录自动标记 `stale`。
- 每个节点只在全部前置依赖为 `completed` 后运行；输出一律进入 `pending_confirmation`，人工确认后才推进下一节点。
- 人工确认必须先通过LangGraph前序和确认数据校验，再提交生产台账与图检查点；后续提交失败必须补偿回滚台账，禁止留下单边`completed`。
- 审核必须返回真实证据、模型/算法、阈值和失败项；能力未安装时返回 `unavailable` 并阻断生产。

## 5. 三次复用强制规则

- 同一界面结构、交互、状态展示或操作组出现 3 次及以上，必须抽成统一 Vue 组件。
- 同一校验、状态转换、停止、恢复、持久化、路由或错误归一化逻辑出现 3 次及以上，必须抽成共享模块或服务。
- 组件允许通过属性、插槽和事件表达差异，禁止复制组件后仅修改名称。
- 共享模块必须有独立正常、异常和边界测试；调用方测试只验证映射，不重复测试内部实现。
- 代码评审必须搜索同构重复；发现第三处时，本次增量必须同时收口既有两处。

## 6. 验收门禁

- 前端不存在生产编排循环；后端不存在绕过 LangGraph 的跨阶段自动推进。
- 生产能力与基础设施扩展点必须能在管理界面查询全部已安装提供方、活动提供方和启用状态；缺少活动绑定时明确阻断。
- 正式生产路径不存在直接调用具体图片模型实现，必须经能力注册表解析。
- 任务中心显示真实服务端 UUID 与真实进程/心跳状态。
- 未安装审核器不会返回 `pass`；失败、停止、超时和 stale 不会被完成结果覆盖。
- 三类及以上重复资产卡、条目操作、颜色预设、停止/恢复和持久化逻辑均使用统一组件或模块。
- 多实例测试必须覆盖并发幂等提交、租约抢占、租约过期、节点失联、晚到结果、租户限流、背压和不同资源池并行；单机测试继续强制同一时刻仅一个重负载任务。
- 合片前必须逐镜验证video/audio/subtitle三元证据使用同一媒体包审核批次；只比较镜头ID或字段非空一律不合格。
### 阶段进度事件

- 阶段状态以服务端持久revision为事件游标；客户端订阅必须携带最后已处理revision，响应只返回更高revision，超时无变化返回`changed=false`。
- 状态写入、revision递增和等待者通知必须位于同一事务锁，禁止固定高频轮询及“先查后等”丢事件；客户端断线后从最后revision恢复。
- 订阅必须支持项目/租户/用户隔离、取消信号、等待超时和并发槽背压；订阅等待不得占用生产资源池，超限明确429，禁止无限创建线程。
### 中断与重启恢复

- 服务端是恢复唯一执行方：重启时按真实任务/进程和LangGraph状态决定继续或失败化，并同步项目阶段、台账、revision与错误证据。
- 前端加载只读取持久事实并显示“继续”入口，禁止因`generating/running`旧记录自动重新提交任何重负载阶段；新任务必须来自用户显式操作或服务端持久恢复器。
- 同一中断状态的恢复展示必须通过统一处理器，覆盖文本、资产、图片、视频、合片、审核、超分和导出；禁止每个页面各自定时重试。
