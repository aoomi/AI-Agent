# AI短剧3D资产生产规范

版本：3.3｜生效日期：2026-08-11｜执行链：FLUX.2 Klein 9B单张45°基准 → TripoSR → Blender Headless七角度 → H3 Ref2VA 3D转2D → Qwen‑Edit局部细化

## 1. 3D适用范围

### 必须3D生成

- 跨镜头反复出现且需要空间连续的场景：宗门、院落、殿堂、房间、街巷、店铺、山门、洞府、擂台。
- 跨镜头反复出现且需要稳定旋转、遮挡或尺寸关系的独立道具：兵器、法器、玉佩、箱柜、桌椅、车辆、机械装置。
- 分镜需要明确机位复现、透视、景深、Depth/Normal/Mask控制的场景和道具。
- 全部剧情服装作为道具子类`costume`独立建模；角色身体模型与服装模型必须分离，禁止把可换服装固化进人物本体。

### 3D与2D混合生成

- 核心人物：3D只承担身体比例、服装大轮廓、站姿、动作、空间位置、遮挡和镜头透视；最终五官、肤质、妆发细节、手指和表情由2D身份链完成。
- 灵兽、怪物、非常规角色：需要稳定体型、动作或多角度时生成3D；面部神态、毛发、鳞片和风格细节由2D链修正。
- 布料、长发、披风：3D用于大形和运动参考，最终褶皱、发丝和材质由2D链覆盖。
- 最终成片中的核心人物面部必须由2D身份链生成，禁止直接使用TripoSR人物模型的人脸渲染图。TripoSR人物只允许用于身体/服装审核、空间坐标与朝向、遮挡和光影辅助。
- 人物3D通道送入2D风格链前必须生成头部强制蒙版；3D仅传递身体、服装、姿态、Depth、Normal和遮挡信息，蒙版内的五官、肤质、表情与口型由2D身份链完整接管。

### 禁止或无需3D生成

- 人物最终脸、面部近景、微表情、嘴型、眼神、皮肤纹理、手部特写。
- 字幕、Logo、屏幕文字、粒子特效、法术光效、烟雾、火焰、流水和纯平面图形。
- 只出现一次、无旋转遮挡需求、不会影响空间连续性的微小道具。
- 远景群演和无需身份一致性的背景人物。

## 2. 输入图规范

- 人物第一张定位基准图固定为`0°正面全身照`：单人物、正常人眼高度、自然A-Pose，脸、双肩、胸口、骨盆、双膝和双脚全部正对镜头，完整发顶/双手/双腿/双脚、纯中性灰背景、无道具、无文字、无裁切；生成模型固定`FLUX.2 Klein 9B`、8-bit、8步、928×1664。
- 人物首张及TripoSR唯一几何输入固定为人工确认的`0°正面全身照`；确认后，人物卡再按`左45°全身、右45°全身、90°侧面全身、180°背面全身、0°正面半身`逐槽生成、逐槽人工确认，合计六格。
- 人物所有全身角度图强制保留构图安全区：最高发顶上方纯背景留白不得少于画高8%，最低鞋底下方纯背景留白不得少于画高3%。8%和3%均为最低值，不是必须精确等于该数值；低于任一最低值必须自动重排构图或重生成。
- 人物固定角度生成参数属于生产硬基线：左右45°使用Qwen Image Edit 2511双参考、`qwen-image-edit-2511-multiple-angles-lora.safetensors`权重`0.35`、Lightning 4步LoRA权重`1.0`、`steps=4`、`CFG=1.0`；提示目标为从正面向对应方向转动35°，机器验收的人脸偏航范围为左`+30°—+60°`、右`-60°—-30°`且滚转绝对值不超过7°。画面必须保留双眼、远侧脸颊及躯干两侧的三分之四特征，不得退化成90°纯侧面或镜像到反方向。
- 90°侧面必须为`88°—92°`纯侧脸且躯干偏离纯侧不超过3°；180°背面不得出现脸和正面胸口；0°正面偏航与滚转绝对值均不得超过7°。方向判定必须同时经过确定性姿态证据与视觉验收，任一失败只重生成当前角度。
- 上述角度提示、方向符号、允许区间、角度LoRA文件/权重、采样步数和CFG必须作为同一版本化配置整体锁定。未经真实人物六格回归、独立软件测试和代码稽查，不得单独修改、回退或用其他模型参数覆盖；每次生成必须在任务元数据记录实际角度目标、LoRA文件/权重、步数、CFG和验收结果。
- 所有全身图必须逐项检查可见的左右臂、腕、手、手指、腿、踝、脚和脚趾；粘连、缺失、多余、重复、断裂、融化或不自然连接的肢体/手指/脚趾一律机器拒绝并重生成当前槽位，禁止进入人工确认。衣物自然遮挡只有在被遮挡部位未呈现畸形时才允许。
- 0°半身照必须为正面平视特写型构图：人物正中央、头顶微小留白、腰部裁切、手部完全在画面外，头部至腰部约占画高75%，双肩不触边、左右留白适中、背景完全纯色无杂物；补强脸部、妆发、领口、近景、表情和口型。
- 六图进入2D分镜链时职责固定：0°半身独占近景人脸身份，0°正面全身基准锁3D结构、体型和服装，左45°/右45°/90°/180°锁对应方向轮廓连续性；六图均参与生成与审核。3D几何链严格只读取人工确认的0°正面全身基准。
- 人物正面近照退出第一槽；需要锁脸时由0°正面半身槽及2D身份链负责，不替代0°正面全身唯一3D输入。
- 道具输入固定为单一完整道具45°三分之二视图；所有边缘、厚度、把手、底部结构尽量可见；纯中性灰背景，无手、无人、无支架、无文字。
- 场景输入固定为正常人眼高度45°空场景全景；必须展示主要空间纵深、入口、墙地关系和固定陈设；禁止人物、文字、拼图和鱼眼畸变。
- 道具和场景的2D资产卡只生成并人工确认上述一张45°基准图，禁止再调用2D模型生成其他角度；确认后自动启动TripoSR与Blender，由Blender七角度RGB/Mask/Depth/Normal自动补齐卡片，其余角度以3D渲染为唯一来源。
- 输入图生成和3D建模不得并行；同一时刻只允许一个重负载任务。

## 3. 自动工作流

1. 前端资产卡片确认资产描述和首张基准图。
2. 人物直接复用已确认的Klein‑9B 0°正面全身基准图；道具和场景仍直接复用各自在资产页生成并确认的唯一45°基准图，3D任务不得再次调用Klein生成第二张参考图。
3. 服务端创建唯一任务ID，记录项目、资产、阶段、进程PID/PGID、心跳、超时和输出路径。
4. TripoSR读取单张参考图，执行去背景、前景归一化、三平面重建和256分辨率Marching Cubes，输出原始GLB。
5. TripoSR权重卸载后启动Blender Headless；禁止同时常驻Klein‑9B、TripoSR和Blender重任务。
6. Blender自动执行：导入→合并对象→应用变换→合并近点→删除松散几何→统一法线→保守减面→居中落地→材质保留→保存Blend→导出清理GLB。
7. Blender固定渲染七角度：`0°正面、左45°、右45°、90°侧面、180°背面、俯视、仰视`，每个角度输出RGB、透明Mask、Depth、Normal辅助通道。
8. Blender额外输出24FPS、96帧、4秒的真实相机源视频；源视频只提供几何、运镜、遮挡与时序，不承担最终五官。
9. 3D→2D转换：人物镜头把Blender源视频和已确认正面定妆照作为两个独立磁盘输入交给MiniMax H3 Ref2VA；H3只负责把3D结果转换为保留结构、空间、遮挡和时序的2D风格结果，禁止把TripoSR、Blender和H3塞入同一Comfy图。
   H3正式提示词前固定串接已安装Context IR Agent生成并落盘`optimized_prompt`；它只做提示词翻译，不修改源视频、身份图或3D通道。Context模型完全卸载并释放Comfy后才启动H3，调用边界见`docs/specs/H3 Context IR提示词优化节点.md`。
10. 2D细化：Qwen‑Edit只读取H3输出成品及已确认身份/服装参考，执行局部修复、人脸调整和服装细化；禁止跳过H3直接用Qwen‑Edit替代3D→2D转换，也禁止两者并行。
11. 2D结果继续执行人物身份、服装、方向、头脚完整、场景/道具连续性和项目画风审核；通过后才能进入分镜画面。
12. 成品归档GLB、Blend、输入图、七角度审核图、辅助通道、清理报告、任务记录和工作流版本。

### 3.1 服装建模、穿衣与入库

1. 资产提取先建立全剧服装清单；日常服、战斗服、礼服、旧装等各自使用稳定`costume_id`，首次版本为`v1`。
2. Klein‑9B只生成一张45°三分之二服装展示图，必须看清正面、肩领/顶面结构、侧面层次、下摆和主要配饰；背景中性且禁止人物、人体模型、衣架文字和多图拼接。
3. 人工确认后TripoSR生成独立服装GLB，Blender完成清理、封闭性/厚度/穿插审核和七角度四通道渲染。
4. `pending_development`：穿衣时先加载不含服装的角色基础体，再按分镜`costume_id@costume_version`加载服装，通过表面变形、蒙皮权重传递和碰撞修正包裹到角色；禁止覆盖角色基础体或服装源资产。当前worker未实现该能力，调用必须返回`capability_not_implemented`，禁止用通用单图TripoSR结果冒充穿衣完成。
5. `pending_development`：穿衣结果必须复核领口、肩、腋下、腰胯、袖口、下摆与肢体穿插；失败只返修当前服装/角色组合。
6. 服装确认后归档到`data/hot/projects/{project_id}/3d/costumes/{costume_id}/`，元数据记录owner、tags、version、status及适配角色；道具栏展示并管理该资产。

## 4. 审核边界

- **TripoSR生成的3D渲染图仅用于审核模型结构、姿态、服装/道具的大致对应关系，不执行面部特征相似度比对；面部一致性只由2D身份审核链锁定。**
- 人物3D必检：单一人体、自然比例、完整头手脚、无多肢、无明显穿模、服装轮廓和主要配饰对应、可支持目标动作。
- 道具3D必检：主体唯一、轮廓闭合、厚度合理、主要部件不缺失、比例和材质分区对应、无悬浮碎片。
- 场景3D必检：可行走空间、墙地关系、入口出口、固定陈设、尺度和主要遮挡关系正确；禁止用TripoSR单物体网格冒充完整可漫游场景，复杂场景必须拆分为建筑主体和独立陈设后组合。
- Blender清理不得改变主体轮廓、服装结构、道具功能部件或场景布局；自动补洞只允许小孔，巨大缺面必须退回参考图或建模阶段。
- 任何3D审核通过均不等于最终画面审核通过；最终交付以2D身份/风格链和分镜画面审核为准。

## 5. 分镜使用规则

- 场景、道具3D可直接用于固定机位、透视、遮挡、景深和镜头轨迹计算；最终画面仍经过2D风格化。
- 人物3D可以提供身体动作、服装大形、光影和空间占位；最终头部、表情、手部和口型必须由2D链重绘。
- 分镜脚本仍为强制上游：3D只执行分镜规定的机位、动作、场景和道具状态，不能替代剧情、镜头时长、台词、情绪和剪辑设计。
- 同一资产全剧复用同一清理GLB；造型变化必须建立新版本并写明生效集数，禁止覆盖旧版本。
- 每个出镜人物在每个镜头都必须携带`costume_id`与`costume_version`；延续也必须重复标注。前后镜头ID变化时系统登记换装事件并加载新服装，AI不得自行选择换装时机。
- 换装是剧情状态而非随机美术变化：撕外衣、换战甲、赴宴礼服、回忆旧装等必须在剧本/分镜中显式发生；缺少服装资产、版本或换装事件时阻断下游。
- 当前人物基准与人物3D仍包含默认服装，只作为既有2D身份/轮廓参考，不代表角色基础体已经服装分离。无服装角色基础体与真实穿衣装配完成验收前，涉及独立服装替换的镜头必须标记`capability_not_implemented`并停止推进。

### 5.1 多角色同框与遮挡合成

- 3D阶段必须分别输出静态背景层、每个人物的站位Mask和全镜头Depth遮挡关系，不得把带3D脸的多人渲染直接作为最终画面。
- 2D合成顺序固定为`背景 → 最远人物 → 中间人物 → 最近人物`；前后次序由摄影机空间中的实际深度排序确定，不得直接用业务Z轴正负号猜测。
- 每个人物必须使用独立Mask和独立2D身份参考生成；衣角、手臂、道具等交叉边缘由2D修复链依据Mask与Depth融合。
- 遮挡只改变可见区域，不得修改人物`facing`、`gaze_target`、身份、服装和空间锚。
- 三人三角站位等复杂镜头必须先记录逐人深度与遮挡表，再按远到近逐层生成；缺少任一人物Mask或深度关系时禁止进入最终合成。

### 5.2 语音时长与动作节奏

- 每镜以TTS真实时长对比分镜`duration`和3D动作时长；绝对偏差超过0.5秒时暂停生产并退回分镜。
- 退回记录必须包含`shot.duration、tts_duration、duration_delta`以及“缩短台词、调整动作、拆分镜头”三类候选方案。
- 未经人工确认，禁止通过强行加速动作、压缩台词、截断尾音或改变角色语速消除偏差。

### 5.3 跨项目资产复用

- 3D资产分为`shared`全局公共资产和`project_private`项目独占资产；项目独占资产禁止跨项目直接读取。
- 公共资产固定存放`data/shared/3d/`，由`registry.json`记录资产ID、类型、版本、来源、许可、SHA-256和依赖。
- 项目引用公共资产时，项目`metadata.yaml`必须记录`shared_from`和精确版本；公共资产升级不得自动修改既有项目，必须执行显式“升级引用版本”并重新审核。
- 项目引用采用版本快照，不得把可变公共目录直接作为生产输入，避免上游更新导致旧项目画面漂移。

## 6. 失败、停止与恢复

- 每个3D重任务必须使用服务端UUID；客户端名称只能作为别名，禁止覆盖历史任务。
- 阶段固定为`queued → klein9b_reference → triposr_reconstruct → blender_cleanup → blender_render → completed/failed`。
- 每阶段持续心跳；超时、停止、服务关闭或看门狗回收必须终止自身进程树并释放重任务锁。
- 单个3D job按当前真实执行器使用分阶段计数：Klein参考图阶段总尝试最多2次（首次+1次重试），TripoSR阶段总尝试最多3次（首次+2次重试），Blender阶段总尝试最多3次（首次+2次重试）；阶段成功后进入下一阶段并使用下一阶段独立计数，单job理论最多8次阶段执行。输入不合格、许可不符、模型/依赖缺失和结构性错误不得自动重试；内存不足必须先释放资源并重新通过内存门禁，才允许占用当前阶段剩余尝试次数。
- 服务重启回收queued/generating/retrying/processing残留状态；完成态不得被停止或晚到结果覆盖。
- 看门狗同时处理“有任务状态但无进程”和“有受管进程但无任务状态”，且只终止当前服务scope和owner token匹配的进程。

### 6.1 系统故障回退与失败证据

- 24小时累计失败只统计已经耗尽单任务尝试并落为`failed`的独立服务端job，不统计job内部attempt。第三个独立job执行并最终失败后立即转为`fallback_review`，禁止自动创建第四个job；等待人工决定修复后重试或降级。输入错误和结构审核失败不得自动降级掩盖。
- 人工批准纯2D回退后，保留0°、左45°、右45°、90°、180°全身图与0°半身身份照共同锁定人物，跳过TripoSR与Blender；身份、风格、服装、方向和连续性审核标准不降低。
- 失败候选不得覆盖已确认版本；输入、局部产物、错误日志、任务上下文和时间戳移入`output/failed/3d/{project_id}/{asset_id}/{job_id}/`。
- 失败证据仅允许人工确认后重试、归档或清理；普通任务不得自动无限重试，也不得因3D降级跳过最终2D审核。

- 业务坐标统一为X向右、Y向上、Z朝向摄影机，单位米；Blender内部Z‑up坐标必须在导入/导出元数据时转换，禁止把Blender轴定义直接泄漏为业务坐标。
- 每个场景第一镜必须登记人物和关键道具的`keyframe=true`坐标；后续镜头必须继承，除非分镜显式修改。摄影机每镜单独指定，不继承上一镜。
- 相邻镜头中`keyframe=true`元素坐标偏差必须小于0.1米；人物相对站位必须符合剧情，摄影机变化必须与景别/运镜可解释。
- 2D结果中主体站位与3D投影偏差必须小于画面宽度10%；超限退回2D空间约束或分镜，不得改脸掩盖站位错误。
- 场景必须保存`layout.yaml`，摄影机必须保存`camera_rig.yaml`；每镜保存camera位置、目标、焦距、景别及资产坐标快照。

## 9. 尺寸、网格和材质门禁

- 人物最大50,000面、道具最大20,000面、场景最大200,000面；超限由Blender保守减面，减面后轮廓和功能部件不得变化。
- GLB必须保留顶点颜色；人物允许输入图映射纹理但只作参考，场景/道具优先程序化材质或独立可追溯纹理。
- 自动审核必须检查非流形边、破面、孤立几何、法线、UV、材质、纹理、场景边界和单位尺度。小孔可自动补洞，主体缺面、错误拓扑或错误结构必须重建。
- 人物默认身高由角色档案确定；缺失时使用1.70米占位并标记`dimension_inferred=true`。道具必须登记长宽高，场景必须登记边界长宽高和平面布局；缺失值可由资产描述推定，但必须进入人工确认。
- TripoSR目标处理时间：人物2分钟内、场景/道具5分钟内；实际超时受统一任务超时和内存门禁控制。

## 10. Blender渲染标准

- Blender固定3.6+，当前本地运行时为5.0.1；仅后台无界面运行。预览Eevee 32采样，最终输出Cycles 64采样；硬件不支持Cycles时任务必须明确失败，不得静默把预览冒充最终结果。
- 人物竖屏输出928×1664；场景/道具标准输出1920×1080。图像PNG，动画MP4。
- 必选角度：0°正面、左45°、右45°、90°侧面、180°背面、俯视、仰视。每个角度必须有RGB、Depth、Normal、Mask；线框为推荐审核通道。
- 标准角度渲染用于结构、姿态、服装/道具和布局审核；人物3D渲染禁止执行面部相似度比对。

## 11. 目录和命名

```text
data/hot/projects/{project_id}/3d/
├── scenes/{scene_id}/{source,textures,renders,metadata.yaml,layout.yaml,camera_rig.yaml}
├── props/{prop_id}/{source,textures,renders,metadata.yaml}
├── costumes/{costume_id}/{source,textures,renders,metadata.yaml}
└── characters/{character_id}/{source,textures,renders,metadata.yaml}
```

- 生产服务可在`output/assets3d/`建立可访问工作副本；人工确认后必须归档到上述`data/hot/projects/`目录，完成项目冷归档后迁移到`data/cold/`。
- 源文件：`{asset_id}.glb/.blend`；纹理：`{asset_id}_{type}.png`；渲染：`{asset_id}_{angle}.png`；辅助通道：`{asset_id}_{angle}_{channel}.png/.exr`；元数据固定`metadata.yaml`。

### 11.1 资产ID、权限与版本冲突

- `{asset_id}`在当前租户资产域内必须全局唯一，禁止2D/3D同名异物或人物、场景、道具跨类型同名。
- 新建或确认归档前必须同时检查2D资产索引、3D当前版本、共享资产索引和待确认候选；发现冲突时阻止写入并返回`资产 ID [xxx] 已存在于 [路径]，请修改 ID 或选择明确版本操作`。
- 禁止静默覆盖。覆盖、建立新版本、升级共享引用都必须由人工确认，并保留旧版、操作者、时间、原因和依赖项目。
- 同名资产的新造型使用版本号或新ID，并记录生效集数；空间锚只能引用已确认的精确资产版本。
- 资产首次提取时由系统生成`{project_id}_{asset_type}_{asset_name}_{version}`；人工改ID必须审批。镜头重绘递增`_vN`并保留旧版本，空间锚通过`shot_id`绑定最新审核通过版本及依赖快照，禁止静默覆盖。

## 12. 审核与终态

- 自动审核全部通过后状态进入`pending_confirmation`，不得直接把3D模型标记为最终成片资产。
- 人工审核结构合理性、空间锚定、光照材质和构图；人物最终2D画面另由2D身份链审核五官相似度。
- 生命周期：`idle → queued → klein9b_reference → triposr_reconstruct → mesh_auditing → blender_cleanup → blender_render → render_auditing → pending_confirmation → completed/failed`。
- 单job严格执行Klein 2次、TripoSR 3次、Blender 3次的独立阶段上限；任一阶段耗尽即转`failed`，不得继续后续阶段。每次重试前必须彻底终止上次进程树并释放模型。24小时内同资产第三个独立job失败后转`fallback_review`，不得自动启动第四个job。

### 12.1 2D与3D冲突仲裁

- 人脸、五官、表情、肤质、手部和口型永远以2D身份/修复链为准，3D头部必须被蒙版覆盖。
- Blender在3D结果交给2D生成器前必须自动输出头部Mask；最终2D链仅可读取被遮罩身体、服装、姿态、Depth与Normal，禁止读取3D五官作为身份依据。
- 2D主体视觉中心与3D投影偏差小于画面宽度10%时，可保留2D构图舒适度，但必须把最终投影偏差写入审核记录。
- 跨镜头关键人物/道具漂移超过0.1米、前后遮挡颠倒、脚底悬空或陷地时，以3D空间锚为准，退回2D生成或修复。
- 3D Depth/Mask与2D动作语义错位时不得静默选择任一结果；先标记`spatial_visual_conflict`，由人工决定修正空间锚或2D动作。
- 每次仲裁必须同步更新分镜约束、2D提示词、3D空间锚、审核结论和后续镜头继承数据，禁止相同冲突重复出现。

## 13. 动态人物与摄影机空间锚

### 13.1 通用镜头结构

- 每镜空间锚必须包含`shot_id、scene_id、duration、characters、camera、spatial_continuity`。
- 人物基础字段为`id、position[x,y,z]、facing[x,y,z]、target_position、gaze_target、keyframe`；位置单位米。
- 经过门、柱、屏风或其他遮挡体时必须登记`occluder_id、occlusion_start_frame、occlusion_end_frame`；2D链按区间逐帧使用人物Mask，禁止遮挡关系突变。
- 原地动作使用`upper_body_action、upper_body_amplitude(large/medium/small)、head_movement(follow_hand/fixed/look_at_target)`；脚底坐标必须不变。
- 行走/奔跑使用`target_position、walk_speed`；普通行走约0.8米/秒，奔跑不低于3.0米/秒；`running、motion_blur`必须显式登记。
- 跳跃使用`jump_type(upward/forward/downward)、jump_arc_height、landing_position`；起跳、最高点和落地三个关键帧必须连续。
- 被打飞、击退、推开使用`force_origin、force_vector、force_magnitude、impact_type(knockback/knockdown/push)、landing_position、impact_pose(falling_back/rolling/tumbling)`；轨迹和速度变化必须符合受力方向。
- 倒下/跪地使用`fall_type(backward/forward/sideways/kneel)、final_position、final_pose(kneeling/sitting/lying)`；倒地终点成为后续镜头继承坐标。
- 抱起/背负/抬行/拖拽使用`interaction_type(carrying/piggyback/lifting/dragging)、interaction_target、carried_by、carried_pose(in_arms/on_back/lying)`；双方相对变换必须绑定，禁止被携带人物独立漂移。
- 站位关系使用`relative_to、relative_position(in_front/behind/left/right/above/below)、distance_to_target`；支持背对、遮挡、并肩、L形和高低差关系。

### 13.2 摄影机运动

- 跟拍：`track_target、tracking_offset、track_lock_axis(x/y/z/none)`。
- 环绕：`orbit_target、orbit_radius、orbit_speed、orbit_direction(clockwise/counterclockwise)`。
- 变焦：`zoom_start、zoom_end、zoom_duration、zoom_easing(smooth/linear/ease_in_out)`。
- 快速切镜：每段登记`cut_type(hard_cut/fade/dissolve)`和`spatial_continuity`；相邻快速镜头可改变摄影机，不得改变未运动人物坐标。
- 摄影机目标、焦距、轨迹、速度和最终构图必须可由分镜脚本解释；禁止为追求动感破坏站位连续。

### 13.3 动态审核

- `spatial_continuity=true`时，所有未声明移动且`keyframe=true`人物/道具相邻镜头坐标偏差小于0.1米。
- 奔跑速度、跳跃弧线、受力方向、落点、倒地方向和携带关系必须与动作文本一致。
- 同一时刻多人互动不得穿模；挡位必须明确前后遮挡，并肩必须同向，L形站位必须分别登记朝向，高低站位必须使用Y轴高度差。
- 快速切镜只允许摄影机变化；人物和道具不得因切镜瞬移。2D输出仍执行小于画面宽度10%的投影偏差门禁。

#### 13.3.1 多机位视线连续性

- 同一场景连续使用3个及以上机位时，主要人物的`gaze_target`必须持续指向同一对象；全景、近景、过肩和反打不得各自重置视线。
- 相邻镜头视线偏移不得超过10°；任何偏移都必须在分镜中写明起点、终点和发生动作。
- 禁止人物在相邻镜头突然从看角色A变为看观众或看天；打破第四面墙等例外必须由分镜显式声明。
- 视线切换必须有承载切换动作的镜头，并记录`gaze_from、gaze_to、gaze_transition_duration`；禁止仅靠切镜瞬时换目标。

### 13.4 标准数据示例

```yaml
shot_id: 090
scene_id: s13
duration: 1.8
spatial_continuity: true
characters:
  - id: protagonist
    position: [0.0, 0.0, 0.0]
    facing: [1.0, 0.0, 0.0]
    force_origin: antagonist
    force_vector: [2.0, 1.5, 2.0]
    force_magnitude: 5.0
    impact_type: knockback
    landing_position: [2.0, 0.0, 2.0]
    impact_pose: falling_back
    keyframe: true
camera:
  position: [0.0, 1.5, 4.0]
  track_target: protagonist
  tracking_offset: [0.0, 0.0, 3.0]
  cut_type: hard_cut
```
