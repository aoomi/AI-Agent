# LoRA 资产强制规范（工业终版）

## 1. 适用范围

- 本项目不自主训练 LoRA，只接入已完成的合规外购 LoRA。
- 题材专属视觉标准存放于 `docs/specs/styles/`；国风浅涂项目必须同时执行 `docs/specs/styles/国风浅涂视觉生成规范.md`。
- 风格 LoRA 与角色 LoRA 必须物理分目录、逻辑分职责，禁止混用、合并或跨权限调用。
- 主力开发负责选型、配置和归档；软件测试 Skill 负责效果与参数验收；稽查 AI 只读检查资产完整性和合规性。

## 2. 全局固定规则

- 全项目统一一个固定基础底模，所有 LoRA 必须完全适配该底模，禁止跨底模、新旧版本或非兼容批次混用。
- 单项目只允许启用一套全局风格 LoRA；项目启动后锁定底模、LoRA 文件、版本、权重和触发词。
- 核心角色一人一个专属角色 LoRA，禁止多人共用、多人打包、跨角色复用。
- 男主、女主、男二、女二、固定反派和常驻配角必须配置专属角色 LoRA；龙套、路人和临时配角可使用底模。
- 单帧唯一合法组合：`固定底模 + 1 个风格 LoRA + 当前人物的 1 个角色 LoRA`，最多加载两个 LoRA。
- 禁止额外叠加氛围、滤镜、美颜、光影、特效或修复类 LoRA。
- 每次生图必须先读取权威 LoRA 索引并完成登记、路径、SHA-256、触发词、底模和许可证校验；校验失败时禁止生成。

## 3. 风格 LoRA

- 只控制光影、色调、笔触、质感、氛围、明暗和画面通透度，不控制人脸、五官、脸型和主体结构。
- 权重固定为 `0.6–0.8`，全剧保持一致，禁止逐集、逐镜头或按景别调整。
- 官方触发词和负面触发词必须原样固化，全剧统一复用。
- 一旦通过验收，全剧禁止替换文件、版本、权重、触发词和批次。

## 4. 角色 LoRA

- 只控制五官、脸型、骨相、个人特征、辨识度和五官比例，不控制风格、光影、色调和画面质感。
- 权重固定为 `0.7–0.85`，同一人物全剧及所有景别保持一致。
- 每个角色必须配置唯一专属触发词，禁止使用模糊通用词或与其他角色共用。
- 远景、中景、近景和特写必须使用同一文件、同一版本、同一权重和同一触发词。
- 禁止用风格 LoRA 代替角色 LoRA 锁脸，禁止通过逐镜头调参修复人物漂移。

## 5. 外购准入标准

- 必须免费或已取得明确商用授权，并保存作者、来源、版本、发布时间、许可证及商用证明。
- 必须提供原版未修改的 Safetensors 权重文件，禁止二次压缩、篡改或仅保存下载链接。
- 必须适配项目固定底模和 `1024×1024` 及以上生成分辨率。
- 原生训练素材应高清、多角度、五官完整；角色素材的服装、发型和妆容应稳定。
- 原生输出不得包含水印、文字、滤镜畸变、畸形五官、过曝、暗部死黑、蜡像脸、塑料质感或过度磨皮。
- 必须保留自然毛孔、轻微肤色差异和真实皮肤肌理。
- 禁止测试版、半成品、残次版以及明显过拟合、欠拟合、特征丢失或画面糊化的 LoRA。
- 禁止接入来源不明、版权不清、加密锁定或无法追溯的网红、名人和非标准 LoRA。

## 6. 资产归档

总目录固定为：

```text
models/loras/<主风格>/
├── 风格LoRA/
└── 人物LoRA/
```

每个外购 LoRA 必须成套归档：

- 原版权重文件。
- 官方触发词和负面触发词文档。
- 作者、来源、版本、发布时间、适配底模、许可证和商用证明。
- 文件大小和 SHA-256。
- 项目实测的多镜头、多角度验收样图。

文件名必须包含中文名称、拼音检索名和底模标识；第三方预览图只能作为参考，不能替代项目实测样图。

## 7. 项目锁定与替换

- 已验收资产在项目全周期冻结，禁止无理由升级、替换、覆盖、改名或调整参数。
- 只有持续崩脸、严重失真、画风割裂、文件损坏或丢失等不可逆缺陷才允许申请替换。
- 替换资产必须保持同底模、同类型、同风格和同参数标准，并完整保留旧版本。
- 替换后必须全量重测相关角色和全剧镜头，禁止局部替换或单镜头特殊适配。
- 新增常驻角色必须沿用当前项目的底模、权重区间、画质标准和归档要求。

## 8. 软件测试 Skill 验收

每集必须增量校验：

1. 全剧只使用一套固定风格 LoRA。
2. 风格权重始终处于 `0.6–0.8` 且没有浮动。
3. 核心人物一人一个专属角色 LoRA，无共用、复用或多人打包。
4. 角色权重始终处于 `0.7–0.85` 且没有镜头差异化调整。
5. 底模、文件版本和触发词全程一致。
6. 单帧 LoRA 数量不超过两个且符合固定组合公式。
7. 画风、五官、脸型、服装、发型和妆容无跳变或漂移。
8. 人脸保留自然肌理，无蜡像、塑料和过度磨皮。
9. 权重、触发词、来源、许可证和生成记录可追溯。
10. 违规项必须退回重生成，禁止豁免。

## 9. 稽查 AI 验收

- 只读核验权重、触发词、合规证明、元数据和验收样图是否齐全。
- 核验底模、权重、触发词和版本是否冻结且未被篡改。
- 核验目录、命名、分类、SHA-256 和历史版本是否完整可追溯。
- 核验替换审批、旧版留存和全量复测记录是否完整。
- 稽查 AI 不参与 LoRA 选型、修改、生成和修复。

## 10. 异常处理

- 单镜头轻微异常不得临时调参、临时换 LoRA 或额外叠加修复 LoRA。
- 持续崩脸、画风波动或特征漂移必须按替换流程更换同底模、同类型的合规资产。
- 文件损坏或丢失必须使用同版本原始文件恢复，并核对 SHA-256。
- 项目不存在自主训练兜底方案；所有 LoRA 缺陷统一通过合规外购资产替换和参数固化处理。
# 项目内人物 LoRA 唯一绑定

- 全剧只允许一套项目级风格 LoRA，项目创建后固定，所有人物共享该画风，不得按人物切换风格。
- 每个出场人物必须独占一个与项目风格、人物性别及当前 SDXL 底模兼容的人物 LoRA；同一项目内禁止两个人物复用同一个人物 LoRA。
- 人物 LoRA 必须在首次定位基准照生成前确定，并把文件名、路径、SHA-256 与底模写入人物资产档案；后续固定角度、分镜画面和修复任务必须沿用该绑定，禁止重新随机选择。
- 分配前必须校验商用许可、索引登记、文件存在、SHA-256、底模和项目内唯一占用；任一校验失败必须阻止生图。
- 人物 LoRA 只负责人物特征倾向，人物身份继续以已确认定位基准照和身份参考模型锁定；不得把通用人物 LoRA 冒充为已训练的专属身份模型。
