# 数据库设计规范

文档版本：1.1
生效日期：2026-08-07
适用角色：后端开发、AI 全自动开发、架构师
文档目录：docs/technical/数据库设计规范.md（原 DATABASE_SCHEMA.md 补充升级）
核心职责：统一全版本数据库命名、字段、索引、迁移、预留、等保合规规则，保障 V1/V2/V3 版本数据库增量兼容、无重构、无数据丢失，满足等保三级数据安全测评要求，支撑产品从本地单机→私有化部署→商业化SaaS平台的全生命周期迭代。
一、规范总则
本规范适用于系统 V1.0（个人本地）、V2.0（私有化部署）、V3.0（SaaS 商业化）全版本数据库设计、建表、字段定义、索引创建、版本迁移工作。所有数据库操作、AI 自动生成数据库代码必须严格遵循本规范，保证全版本数据结构统一、增量兼容、可迭代、可回溯。
核心原则：增量迭代、向下兼容、禁止删改存量字段、预留扩展空间、迁移脚本幂等化；数据安全分层落地，V1/V2 满足基础数据安全，【仅 V3】 完整落地等保三级数据库强制标准。
补充等保说明：等保三级为公网 SaaS 系统强制测评标准，V1 本地单机、V2 内网私有化无需完整落地严苛数据库三级规则，仅执行基础安全约束；V3 云端全量启用数据库等保全部要求。
产品迭代适配说明（新增）：本规范预埋多租户、数据隔离、付费权限、审计溯源底层能力，适配产品长期商业化愿景，做到前期不用、后期不拆、上线不重构，支撑个人免费、企业私有化、公有云SaaS商业化三种商业模式平滑迭代。

2.2 历史表数据规则
- 历史表必须包含：operation_type（INSERT/UPDATE/DELETE）、operator_id、operated_at。
- 历史表不包含扩展字段，所有字段全量平铺，保证数据溯源纯净、可审计。

3.3 字段通用约束
- 核心业务字段禁止为 NULL，必须设置默认值，避免空值报错
- 状态字段统一默认值，保证新增数据状态可控
- 所有 VARCHAR 字段必须有明确长度定义
- 业务唯一字段必须配置唯一索引，杜绝重复数据
- 等保通用约束：全版本禁止明文存储手机号、身份证、支付密钥、授权码等敏感字段

4.1 版本化扩展字段规则
extend_json 必须严格遵守：
- 写入必须携带 schema_version 版本字段
- 禁止无版本裸 JSON 数据
- 读取强制校验版本，向下兼容
- 迭代仅增量新增属性，不删除旧字段
等保补充：【仅 V3】extend_json 中存储的隐私、付费配置字段必须开启字段加密存储。
商业化预留新增（适配全版本）：所有业务表预留 tenant_id 租户字段、license_id 授权字段，V1/V2 静默兼容不启用，V3 全局启用多租户数据隔离，彻底避免后期SaaS化重构数据表结构。
五、索引设计原则
5.1 基础索引规则
- 高频查询字段必须建索引
- 联合索引遵循最左前缀
- 严控索引数量，避免拖慢写入
- 唯一业务字段必须唯一索引
5.2 全版本索引兼容规则
- V1 存量索引禁止删除修改，V2/V3 仅增量新增
- 新增索引兼容低版本存量数据
等保补充【仅 V3】：
1. 租户 ID、用户 ID、手机号、订单号等高频审计字段必须建立联合索引，支持快速审计检索；
2. 禁止无索引全表查询接口，规避数据库慢日志审计违规。
商业化优化新增：V3 所有租户关联表必须建立 tenant_id + 业务主键 联合唯一索引，杜绝多租户数据串数据、越权查询问题，保障SaaS多租户数据隔离安全。
六、数据库迁移脚本规范
6.1 迁移核心原则
- 幂等优先，脚本可重复执行无报错
- 只新增，不删改存量表 / 字段
- 版本化区分 V1/V2/V3 迁移脚本
- 配套回滚脚本，支持降级
6.2 迁移脚本命名规范
V{版本号}_{时间戳}_{功能描述}.sql
示例：V1.0_20260807_add_project_extend.sql
6.3 数据迁移兼容规则
低版本可平滑升级至高版本，不破坏存量数据
等保补充【仅 V3】：
1. 所有迁移操作写入数据库审计日志；
2. 迁移脚本禁止清空、批量删除业务数据；
3. 迁移过程自动脱敏敏感字段，避免明文导出。
商业化合规新增：V2升级V3迁移脚本必须自动补全 tenant_id 租户默认值、补齐数据分级标识，实现私有化客户平滑迁移至SaaS平台，无数据丢失、无合规漏洞。
七、V1/V2/V3 版本预留字段规则
7.1 V1.0
仅基础字段，租户 / 计费仅 JSON 预留，无物理表，适配个人单机免费使用场景，无复杂权限与合规体系。
7.2 V2.0
增量授权、团队字段，SaaS 能力 JSON 预留，适配企业私有化部署，支持内网团队协作、授权管控，满足基础企业安全要求。
7.3 V3.0
释放全部预留，新增租户、账单、风控物理表，落地多租户隔离、付费计费、安全风控、等保三级全量合规，适配公网商业化SaaS运营。
全局预埋规则（新增）：所有版本迭代只增不减、只扩不删，所有商业化、合规化字段提前预埋，杜绝产品迭代中后期大规模数据表重构、数据迁移风险。
八、等保三级数据库强制合规规范
8.1 适用范围区分
1. V1.0 本地单机、V2.0 私有化内网：仅执行本章节【全版本通用】条款，【仅 V3】 条款无需落地；
2. V3.0 公网 SaaS 平台：本章所有条款强制落地，为等保三级数据库测评必查项。

8.3 数据库权限等保规范
8.3.1 最小权限原则（全版本强制）
- 业务账号仅拥有对应表增删改查，禁止赋予 DROP/ALTER/ALTER USER 等高权限；
- 开发、测试、生产数据库账号完全隔离，禁止混用；
8.3.2 三员分立数据库账号【仅 V3】
数据库层面拆分三类独立账号，权限完全隔离，满足等保三员要求：
角色
权限范围
系统库管
仅 DDL 建表、迁移权限，无业务数据查询 / 修改权限
安全管理员
仅可配置加密、脱敏、审计规则，无法修改业务数据
审计管理员
仅 SELECT 查询审计历史表，无任何数据写入、删除权限
8.3.3 完整口令策略规范（全版本强制，等保必测）
- 口令复杂度：数据库运维及业务账号密码长度不低于 12 位，必须包含大小写字母、数字、特殊符号，严格禁止弱口令、简易组合密码。
- 口令轮换机制：密码有效期不超过 90 天，到期强制提醒更换，禁止长期使用固定密码。
- 口令复用限制：禁止重复使用最近 5 次历史密码，杜绝循环复用旧密码风险。
- 首次登录强制改密：新建数据库账号、重置密码后的账号，首次登录必须主动修改初始密码，禁止沿用默认密码。
- 运维会话超时：数据库运维终端闲置 15 分钟自动退出、断开会话，防止挂账未退出导致越权操作。
- 登录锁定强化：连续 5 次登录失败自动锁定账号，锁定时长不少于 30 分钟，杜绝暴力破解行为。
8.3.4 账号安全约束（全版本）
全版本数据库运维账号、业务连接账号严格执行以上口令策略安全基线，V3 云端额外叠加三员分立、登录锁定、运维超时等强约束，从账号底层杜绝爆破、盗用、弱口令风险。
8.4 敏感数据加密与脱敏规范
8.4.1 存储加密（全版本）
L3、L4 级敏感字段统一采用对称加密存储，密钥独立管理，禁止硬编码入库；
8.4.2 传输加密【仅 V3】
云端数据库连接强制 TLS 1.3 加密传输，关闭明文 TCP 连接，防止数据传输窃听；
8.4.3 输出脱敏（全版本）
所有后台列表、前端展示、接口返回、文件导出、系统日志、数据库查询结果中的敏感数据，必须强制脱敏输出，禁止明文落地、明文展示，全版本统一强制执行。

8.5 数据库审计规范（等保核心测评项）
1. 全版本基础审计：所有 INSERT/UPDATE/DELETE 操作自动写入 {表名}_history 历史变更表，记录操作人、时间、变更前后数据；
2. 【仅 V3】强制增强审计：
- 数据库慢查询、登录、权限变更、批量导出全部独立审计日志；
- 审计日志不可删除、不可修改，数据库层锁定历史表 DROP/ALTER 权限；
- 日志留存周期：云端永久归档，满足等保长期溯源要求；
- 审计日志单独库存储，与业务库物理隔离。
商业化溯源新增：V3新增付费数据变更专项审计，账单、授权、套餐变更操作单独留痕，适配商业化对账、售后溯源、合规取证场景。
8.6 备份与灾备等保规范
1. 全版本通用备份规则：自动定时全量 + 增量备份，备份文件加密存储；
2. 【仅 V3】等保强制灾备：
- 跨机房异地双备份，防止单机房数据丢失；
- 按月执行数据恢复演练，留存恢复记录用于等保测评；
- 备份文件访问单独权限管控，禁止随意下载敏感备份。
8.7 数据库入侵与风险防护规范
本小节统一收敛数据库攻击防护、访问管控、会话安全、漏洞治理、资源风控所有规则，去除重复冗余内容，全版本兜底、V3 强化落地，完全匹配等保三级「入侵防范、资源管控、风险闭环」测评要求。
8.7.1 基础防护规则（全版本强制）
- 防 SQL 注入强制约束：所有手动开发、AI 自动生成的 SQL 必须使用预编译参数化查询，严格禁止字符串拼接 SQL、动态裸 SQL 执行，从底层杜绝注入漏洞，为全版本永久红线。
- 数据库会话安全管控：统一限制数据库闲置连接最大超时时间，超时自动回收销毁会话、释放连接资源；禁止非法持久化连接、闲置挂账会话，规避未退出运维会话引发的越权操作风险。
- 高危 SQL 语句永久禁用：编码层、AI 生成层双重拦截无条件 DELETE、TRUNCATE、DROP、ALTER、RENAME 等高风险语句；批量删改必须携带精准业务筛选条件、限制单次执行行数，高危数据操作强制预留人工审核拦截机制，禁止直接自动化执行。
8.7.2 网络访问白名单管控【仅 V3】
- 云端生产数据库严格禁止公网端口暴露、公网直连，仅放行内网服务、VPN 运维白名单 IP 段接入，无白名单权限一律拦截拒绝连接。
- 所有远程数据库运维、数据变更、权限调整操作，必须叠加账号双因素 2FA 认证，单密码校验不通过、禁止执行任何数据库运维操作。
8.7.3 常态化漏洞闭环治理【仅 V3】
- 建立月度数据库专项漏洞扫描机制，覆盖数据库版本漏洞、配置缺陷、弱口令账号、未加密敏感字段、权限过宽、慢查询风险等全部维度，建立标准化漏洞台账。
- 严格执行分级整改闭环：高危漏洞 24 小时内完成修复、中风险漏洞 7 日内整改完毕、低风险漏洞限期归档复盘，所有扫描报告、整改记录、复查记录永久归档，满足等保风险溯源要求。
8.7.4 数据库资源访问最小权限管控（全版本强化）
- 生产、测试、开发数据库环境完全物理隔离、账号隔离、网络隔离，严格禁止跨环境数据导出、跨环境权限复用、跨环境随意访问。
- 所有数据库账号严格遵循最小权限原则，按需分配业务必需的增删改查权限，禁止批量授权、超权限赋权、预留闲置高权限账号。
- 定期清理废弃数据库账号、闲置权限、冗余授权，杜绝僵尸账号带来的安全风险。
8.8 AI 开发数据库等保强制红线（全版本）
1. AI 自动建表、新增字段必须区分数据分级，敏感字段自动加密配置；
2. AI 禁止生成无审计、无脱敏、无权限校验的数据库 CRUD 逻辑；
3. AI 生成迁移脚本必须配套审计、备份前置逻辑，禁止直接批量删改业务数据；
4. V3 分支 AI 代码自动校验数据库三员、异地备份、TLS 传输等保规则，不合规拦截提交。
