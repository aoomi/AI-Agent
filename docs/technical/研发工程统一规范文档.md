
# 研发工程统一规范
文档版本：1.4
生效日期：2026-08-07
存放路径：docs/technical/研发工程统一规范文档.md
关联顶层文档：系统架构设计.md（顶层总纲，本规范为落地执行细则）
适用角色：前后端开发、AI全自动开发、架构师、测试、运维
项目愿景：支撑 V1 本地单机 → V2 私有化部署 → V3 SaaS 商业化平滑迭代，坚持增量迭代、零架构重构、零破坏性变更；统一契约层可信源，落地多租户物理隔离、等保三级合规、商业化计费、多行业合规隔离、供应链安全、全链路可观测与自愈能力，建立AI优先、标准化、可量产、可合规审计的研发工程体系。
一、文档整体约束总则
1. 层级优先级：《系统架构设计.md》优先级最高，本规范为工程落地细则，所有开发必须双向遵从。
2. 版本隔离管控：严格区分 V1/V2/V3 能力边界，禁止将V3专属逻辑硬编码至V1/V2分支，杜绝版本混杂。
3. 合规统一收口：所有研发产出对齐《数据库设计规范.md》数据分级、加密、脱敏、审计标准，全链路统一合规口径。
4. AI强制校验：AI生成所有工程产物必须全自动校验本规范红线，不合规直接拦截入库，人工开发同等自查。
5. 迭代铁律：仅增量新增，禁止修改/删除存量结构与逻辑；所有变更必须配套幂等、可回滚、多版本兼容的迁移脚本。
二、目录工程规范（对齐架构 11.1 目录归属）
项目目录、层级、文件归属和动态资源位置只由根目录《DIRECTORY_README.md》定义。本规范仅要求实现前完成归属检查，禁止复制或维护第二份目录表。
三、全工程统一命名规范（对齐架构 11.2）
全工程通用命名只由根目录《AI_EXECUTION_NAMING_RULES.md》定义。数据库、API 和插件章节只能增加本领域约束，不得重新定义通用格式。
四、插件与 Skill 工程开发规范（对齐第十章扩展机制）
4.1 插件新增完整流程（强制增加版本兼容校验）
1. 新建插件独立目录；
2. 编写 manifest.yaml，声明能力、版本兼容范围、所需权限；
3. 实现Skill统一入口 execute(input, context) -> dict；
4. 开发前端插槽组件并完成前端注册；
5. 全局Registry注册插件；
6. 强制版本兼容校验：版本不匹配、权限越界、依赖缺失则直接拦截加载，禁止非法插件运行。
4.2 分版本插件能力约束
- V1 本地版：仅内置短剧插件，无自定义插件、无插件市场。
- V2 私有化版：支持企业内部私有插件，禁止接入公网插件市场。
- V3 SaaS版【仅V3】：内置+租户私有+公共市场三层隔离，三方插件强制沙箱运行、权限显性授权。
4.3 多行业插件隔离工程要求
1. 强监管行业插件与短剧业务物理目录隔离，禁止跨目录导入依赖。
2. 行业插件独立配置数据留存、脱敏、审计规则，不通用、不污染基础业务。
3. 插件间禁止直接耦合调用，统一通过全局能力总线调度。
4.4 V3 插件市场工程准入规范
1. 上架插件必须提供完整依赖清单与安全扫描报告。
2. 插件所有系统能力必须显性声明，禁止隐式越权调用。
3. 插件运行数据、缓存、存储强制绑定 tenant_id【仅V3】，杜绝跨租户串数。
五、代码开发红线（全版本禁止行为，对齐架构 11.3）
5.1 通用高危禁止项
- 禁止业务逻辑侵入 platform/、.kernel/ 内核目录。
- 禁止硬编码密钥、路径、环境参数，所有敏感配置收敛至配置中心。
- 禁止插件跨包直接import耦合，统一总线调用。
- 禁止自定义插件无权限调用 io/subprocess/os 高危能力。
- 禁止前端插件直接引用内核UI组件，扩展仅允许官方插槽。
- 禁止裸捕获异常、魔法数字、无注释、硬编码枚举，异常必须脱敏分级上报。
- 禁止运行时篡改、写入源码目录文件。
- 禁止批量数据操作无审计、无TraceID、无操作人溯源。
- 禁止L3/L4敏感数据明文打印、明文日志、明文传输。
- 禁止AI代码跳过规范校验、兼容校验、审计埋点。
5.2 V3 SaaS 专属红线
- 所有业务、插件、Skill 查询必须携带 tenant_id 隔离条件【仅V3】，禁止裸查全量数据。
- 禁止插件绕过鉴权越权访问跨租户数据【仅V3】。
- 计费、账单、额度逻辑仅允许在 server/billing/ 实现【仅V3】，业务层散落计费逻辑视为违规。
六、数据安全工程规范（对齐第十三章插件 & Skill 安全、数据库规范）
1. 数据分级落地：自动识别 L1/L2/L3/L4 数据，按等级适配存储、展示、传输规则。
2. 全链路加密脱敏：L3/L4敏感字段加密入库，接口、导出、日志、模型输入统一脱敏，无明文暴露。
3. 数据变更留痕：所有数据表变更写入历史表，记录操作人、租户、项目、TraceID与变更内容。
4. AI行为全量审计：Skill执行、插件配置、模型调用统一接入 server/audit/，作为计费、合规、溯源唯一依据。
5. 灾备能力按《docs/product/产品迭代规划.md》启用；所有已启用版本必须验证备份可恢复，核心数据加密存储。
6. AI上下文隔离：多项目、多租户、多行业、多会话上下文物理隔离，杜绝Prompt串扰与数据泄露。
七、版本兼容工程强制红线（对齐第十四章 AI 代码兼容红线）
1. 结构零破坏迭代：仅增量新增，禁止修改、删除、覆盖存量表、字段、接口、配置。
2. 低版本兼容兜底：V1/V2独有能力通过扩展字段/动态配置实现，不改动底层结构。
3. 高版本向下兼容：V3新增租户、计费、审计能力必须适配低版本读取逻辑。
4. 禁止单版本硬编码：所有逻辑必须具备版本分支兜底，禁止仅适配单一版本。
5. 变更可回滚：所有结构、配置变更配套版本化、幂等、可一键回滚迁移脚本。
6. 模型配置兼容：模型升级、灰度、回滚仅改配置、不改业务代码，保证全版本平滑过渡。
八、多租户商业化工程规范（对齐第十五章 V3 商业化规范）
【仅V3】分支强制落地，V1/V2无需开发对应逻辑：
1. 所有业务表必含 tenant_id，建立联合索引，杜绝跨租户查询漏洞。
2. 租户资源配额（调用、存储、并发）统一在租户层集中管控。
3. 租户注销自动软删除全量租户数据，合规满足等保数据销毁要求。
4. 计费、扣费、用量日志全链路审计，作为唯一对账依据。
九、模型全生命周期工程规范（新增模型管理落地细则）
1. 模型配置中心化：所有模型参数、权重、地址统一注册至全局Registry，业务代码零硬编码。
2. 全生命周期管控：支持注册、灰度、切换、回滚、下线，纯配置驱动，无业务代码改动。
3. 缓存能力按《docs/product/产品迭代规划.md》启用；工程实现必须支持过期清理、容量限制和适用范围隔离。
4. 模型安全校验：权重文件哈希校验，启动拦截篡改、破损、非法模型。
5. 模型调用审计：所有调用关联TraceID、租户、Token消耗，纳入计费与合规体系。
十、可观测性工程统一标准（对齐十六、十九章链路 & AI 审计）
1. 全链路唯一 TraceID 贯穿前端、后端、Skill、队列、渲染、模型调用。
2. 所有日志强制携带 TraceID、操作人、项目ID、租户ID（V3）。
3. AI智能体执行全维度审计留痕，支撑计费、溯源、问题排查。
4. V3链路日志租户隔离存储、长期归档、支持合规导出【仅V3】。
十一、故障自愈与降级工程规范（对齐第十七章）
1. AI模型自愈降级：超时、报错、熔断自动切换备用模型、智能重试，杜绝任务卡死。
2. 渲染服务容错：ComfyUI异常自动停流、缓存任务、断点续跑，保障无人值守量产稳定。
3. 中间件故障兜底：数据库/Redis/队列异常自动降级、本地缓存兜底、请求重试。
4. 自愈能力按《docs/product/产品迭代规划.md》启用；工程实现必须提供有限重试、检查点、接管条件和失败出口。
5. 任务优先级保障：高优量产任务优先调度恢复，低优任务限流兜底。
十二、四层配置分层工程规范（对齐第十八章）
配置优先级：用户级 > 项目级 > 租户级(V3) > 部署级，所有配置禁止代码硬编码。
1. 部署级：端口、日志、内核参数，运维全局管控。
2. 租户级【仅V3】：配额、合规开关、模型偏好，租户管理员配置。
3. 项目级：工作流、题材、集数等项目专属参数。
4. 用户级：界面、快捷键、个人偏好，用户私有生效。
十三、第三方依赖供应链工程规范（对齐第二十章）
1. 依赖版本锁定：所有Python/NPM依赖固定完整版本，禁止模糊升级，规避兼容故障。
2. 自动化安全扫描：新增/更新依赖必须漏洞扫描、恶意检测，高危依赖禁止入库。
3. 许可证合规：严格校验开源许可证，规避商业化侵权风险。
4. 资源资产台账：模型、依赖、外部资源留存版本、哈希、来源记录，全程可溯源。
5. 供应链防投毒：禁止未知来源依赖、未校验模型，外部资源双重校验。
十四、V3 开放 API 工程规范（对齐第二十一章）
【仅V3】分支落地，对外生态统一标准化API能力：
1. API语义化迭代，旧接口长期兼容，禁止破坏性变更。
2. 统一鉴权、IP白名单、限流、租户隔离。
3. 调用量联动计费统计、自动生成用量账单。
4. 接口文档、错误码、返回结构标准化、自动化生成。
十五、版本能力工程落地对照表（和架构演进表保持一致）
V1.0/V2.0/V3.0 的产品能力、交付边界和启用条件只由《docs/product/产品迭代规划.md》定义。本规范仅维护已获准能力的工程实现细则，不复制版本能力表。
十六、研发交付与变更工程规范
1. 文档代码同步：所有功能、结构、配置变更必须同步更新文档与迁移脚本。
2. AI全自动合规校验：AI产出强制红线校验，违规直接拦截。
3. 上线卡点校验：安全扫描、合规校验、隔离测试、链路校验、自愈测试全量通过方可上线。
4. 跨版本平滑迁移：V1→V2、V2→V3配套自动化迁移脚本，自动补全合规与租户字段。
5. 分支纯净管控：各版本分支仅保留对应能力，无冗余、无跨版本残留逻辑。
6. 量产稳定兜底：所有版本支持无人值守量产、故障自愈、合规溯源。
7. 修复回归强制要求：任何问题修复后，必须识别并逐项实测所有可能受影响的关联功能、上下游流程、接口、状态、持久化与界面交互；缺少真实回归验证不得判定完成或交付。
