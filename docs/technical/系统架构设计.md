# AI Agent 系统架构

版本：2.2
生效日期：2026-08-11

## 1. 架构目标

平台以可插拔 Skill 为能力单元，以独立智能体为执行主体，以版本化契约连接前端、平台和业务插件，支持本地、私有化及多租户部署。

## 2. 分层边界

| 层级 | 唯一职责 | 禁止内容 |
|---|---|---|
| `frontend/` | 平台壳、任务中心、插件插槽 | 业务流程实现、伪造服务状态 |
| `platform/` | 身份、权限、配置、任务、事件、模型网关、插件生命周期 | 短剧等行业逻辑 |
| `plugins/` | Skill、业务流程及插件 UI | 绕过平台鉴权、跨插件私有依赖 |
| `shared/contracts/` | 跨层类型与 JSON Schema | 运行时业务逻辑 |

目录归属以根目录 `DIRECTORY_README.md` 为准。

## 3. 核心运行链路

用户请求经身份与授权校验进入平台；平台解析 Skill、智能体配置和模型绑定，创建可追踪任务；平台适配层中的 LangGraph 编排器负责可恢复工作流，核心调度器只承载平台生命周期与授权边界；事件投影更新任务状态；前端通过服务和 Store 展示真实状态与产物。

### 3.1 并发与负载均衡

- API实例通过共享工作节点发现、健康心跳、可用内存、活动数和队列深度选择执行节点；任务以owner/generation租约隔离，物理执行前与结果提交前均复核所有权。
- 节点内采用可配置资源池调度，而不是一把全局锁：`accelerator`串行保护统一内存GPU，`cpu-media`允许受限音频并发，`control`允许状态、确认和停止并发。
- 每个资源池独立配置容量、队列上限、优先级、超时与取消；健康接口公开`active_items`和池级容量/活动/排队快照。队列达到上限时执行背压，不得无限接收。
- 资源调度、节点发现、负载路由、任务仓库、租约、生产台账和LangGraph检查点均通过扩展注册表绑定；替换为PostgreSQL/Redis等分布式提供方时不得修改短剧业务流程。

### 3.2 生产权威台账（ProductionLedger）

- 生产结果以`generation + revision`执行CAS，旧代不得覆盖新代，同代revision必须单调递增。
- `content_fingerprint + audit_batch_id`是媒体证据的原子提交边界；指纹、批次、代际、生产证据、审核证据和confirmation必须一致提交或整体回滚。
- Graph提交与业务结果写回位于同一SQLite写事务围栏内；取消与提交线性化，提交前后均复核租约、代际和取消裁决。（源于M9.183/192）

### 3.3 晚到响应隔离

- 异步响应必须绑定`project_id + session_id + epoch`；项目切换、停止或新代启动后，旧代响应在持久化前丢弃。
- 同项目同阶段采用single-flight，只允许一个权威执行体；旧flight的响应、异常和finally不得写入或释放新flight。（源于M9.179/180/184）

### 3.4 资源等待状态机

- `waiting_memory`是任务仓库持久子状态，投影到LangGraph时统一为`queued`，不得冒充图生命周期。
- 只有ComfyUI释放窗口或队列确认空闲后才允许进入有限、可取消的内存等待；非释放窗口立即拒绝，等待超时必须失败关闭。（源于M9.167/172）

## 4. Skill 与智能体

- 每个 Skill manifest 声明身份、入口、权限、输入输出及兼容版本。
- 每个激活 Skill 生成隔离智能体，生命周期转换必须封闭。
- 每个行业业务流程对应独立 Skill 机器人，并可独立绑定已注册模型。
- 开发 Skill 可按授权写入；稽查 Skill 永久只读。
- 插件间只通过公共契约、任务和事件协作。

## 5. 模型网关与配置

- 模型必须先进入平台注册表，声明提供方、能力、上下文长度、可用状态和约束。
- 智能体只能绑定满足 Skill 能力要求且当前可用的模型。
- 部署级、租户级、项目级、用户级配置按范围合并并版本化。
- 对话生成的配置或任务先形成可确认提案，确认后执行并留痕。
- 未配置真实模型时明确失败，不产生模拟成功结果。
- 生产能力注册表支持同一能力多提供方共存：以`capability + provider_id`作为唯一键，按健康、启用状态和优先级选择，同优先级轮转。插件提供方与内置提供方互不覆盖。
- 默认调用不对失败任务自动切换提供方，避免重复生成、重复扣费或双写；仅幂等且显式允许安全回退的调用可顺序尝试后备提供方。

## 6. 任务、事件与恢复

- 任务、事件和检查点统一携带 `tenant_id`、`project_id`、`identity_id`、`request_id`、`trace_id`。
- 任务状态由服务端事件投影，前端不得自行伪造。
- 取消、失败、人工关口、恢复和终态转换保持幂等。
- 服务重启后从持久检查点恢复，不绕过人工确认。

## 7. 前端扩展

- 平台壳只承载平台导航、任务中心和 Toolbar、Sidebar、Canvas、Navigation、Settings 插槽。
- 插件通过注册表装载自己的界面、服务适配与 UI 状态。
- 短剧原版工作台位于 `plugins/builtin/short_drama/frontend/`，用户可见视觉与交互保持迁移基线。
- UI 状态与项目、任务、资产等业务状态分离。

## 8. 安全与隔离

- 所有资源访问先完成身份范围和权限校验，跨租户、项目、用户及智能体默认拒绝。
- 密钥不进入源码、前端、日志和普通配置；敏感字段按分级规则加密或脱敏。
- Skill、模型调用、配置变更、任务变更及导出均写入审计记录。
- 插件签名、进程沙箱、供应链扫描和生产灾备在完成验收前保持未交付状态。

### 8.1 可观测性持久导出

- 统一`RecordExporter`扩展点输出JSONL持久记录和Prometheus textfile原子快照；日志、跨度、指标快照和告警复用同一导出契约。
- 敏感字段在注册、记录、快照和导出四层过滤；秘密字段、非有限指标、非法指标名/标签或畸形快照一律拒绝，不得降级写盘。（源于M9.197）

## 9. 兼容与演进

- 公共契约显式版本化；破坏性变更必须提供迁移和回滚路径。
- 产品版本范围以 `docs/product/产品迭代规划.md` 为准。
- 产品决定以 `docs/product/PRODUCT_DECISIONS.md` 为准。
- 命名、测试、部署和安全规则分别引用其唯一职责文档，不在本文复制。

## 基础设施提供方生命周期

- 注册键为`extension_point + provider_id`，允许同一扩展点安装多个实现；运行时只解析唯一`active`提供方。
- 生命周期为安装→启用→激活→回滚/停用→卸载。内置升级只刷新内置provider，不得覆盖插件provider或改变插件活动绑定。
- 无状态且明确声明可热切换的实现可在请求边界切换；存储、检查点、任务仓库、租约和发现等有状态实现默认不可热切换，必须排空、迁移、重启并验证恢复。
- 存在`inflight`任务的提供方不得卸载、替换或被能力级覆盖；必须等待任务自然终态或完成显式排空。注册表在替换和卸载边界原子复核真实inflight计数。（源于M9.176）
- 管理面负责查询和变更绑定，数据面只使用已解析活动提供方；没有活动绑定、活动提供方被禁用或实例创建失败时立即阻断，不静默降级。
## 阶段事件与客户端同步

- 项目阶段记录包含单调`revision`；`stage/watch`以`tenant + user + project + stage + after_revision`为订阅键，通过Condition长轮询等待下一版本。
- 写事务保存新revision后在同一RLock内`notify_all`，订阅读取与进入等待也使用同一Condition，保证无丢唤醒；网络响应在释放锁后发送。
- 当前单节点默认最多128个等待订阅、每次20秒且硬上限25秒；超限429背压。未来可由基础设施扩展点替换为Redis Streams/PostgreSQL NOTIFY，前端游标契约保持不变。
## 重启恢复职责

- 启动恢复器读取LangGraph、统一任务仓库、真实进程和项目阶段；不可恢复的同步阶段在服务端原子写failed并递增项目revision，事件通道通知客户端。
- 客户端项目加载不得启动生产，只把中断阶段映射成可继续状态。这样刷新页面、多个浏览器和服务重启不会重复创建同一重负载任务。
- 恢复映射集中维护；新增生产阶段必须同时登记LangGraph阶段、项目存储阶段和用户继续入口，缺任一映射即不得声明可恢复。
- 新增Stage还必须同步登记启动恢复器、LangGraph阶段映射、项目存储投影和前端继续入口；CI契约门禁必须拦截任一处缺失的阶段，禁止仅靠运行时发现。
