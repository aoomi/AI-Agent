
# AI 通用 API 接口开发规范
标准文件名：AI_API_SPEC.md
适用：全项目通用、无业务绑定，适配前后端、内部服务接口
强制绑定：四大全局规范、开发主规范、代码稽查规范
核心机制：格式统一、返回统一、校验统一、安全合规、增量可迭代、零歧义
一、API开发AI身份与权责（固定铁律）
1. 身份定位：专职标准化API接口开发、定义、调试、落地，遵循全局开发规范。
2. 核心权责：负责路由定义、参数校验、请求处理、响应封装、异常捕获、接口文档同步。
3. 工作边界：仅做接口层转发与封装，禁止私自新增业务、扩功能、修改架构，禁止接口层写核心业务逻辑。
4. 核心使命：产出统一、安全、合规、可复用、可迭代、零负债的标准化接口。
二、全局强制铁律（最高优先级）
1. 强制读档：接口开发前必须读取本文档+主规范，对齐标准，禁止随意定义接口。
2. 全局格式统一：路由、请求方式、入参、出参、状态码、异常返回全程无特例。
3. 强制参数前置校验：所有入参前置校验，非法参数直接拦截，禁止透传业务层、禁止裸抛异常。
4. 统一响应强制：所有成功/失败接口，必须使用全局固定响应结构体，禁止自定义返回。
5. 安全强制校验：按需校验登录态、权限、防重放，敏感数据强制脱敏。
6. 提交接口幂等强制：新增、编辑、提交类接口必须支持幂等，防重复操作。
7. 增量版本兼容：仅新增、不修改存量接口，不改动路由、字段、类型，旧接口永久兼容。
8. 文档同步：接口开发、迭代后同步更新文档，代码与文档100%匹配。
9. 服从双AI机制：单接口随子任务自动续跑，完整接口模块完工后触发稽核、整改、人工验收。
三、接口基础全局规范
1. 路由与字段命名统一引用根目录《AI_EXECUTION_NAMING_RULES.md》，本文不维护第二份通用命名规则。
2. 请求方式语义唯一：GET查、POST增、PUT全改、PATCH局部改、DELETE删，禁止混用
3. 版本规范：所有接口必带版本，默认v1，迭代升级v2/v3，增量不破坏
4. 传参规范：GET用Query、POST/PUT/PATCH用JSON Body、文件上传用multipart/form-data
5. 头尾规范：统一Token鉴权请求头，统一跨域、缓存响应头，禁止随意自定义头部
6. 超时分级规范：查询15s、普通提交30s、上传/批量60s，超时统一返回500标准提示
四、入参校验 + 字段全局统一规范
1. 三重校验：基础校验（非空、类型、长度、范围、正则）+ 业务校验（存在性、状态、权限）+ 前置拦截
2. 字段格式和跨端转换以《AI_EXECUTION_NAMING_RULES.md》的契约边界为准，前后端字段类型和语义必须一致。
3. 禁止硬编码：状态、类型、标识全部后端枚举管控，接口无零散硬编码文本
4. 空值统一规则：空对象返回{}、空列表返回[]，禁止返回null/undefined，严控空字符串滥用
5. 枚举强制绑定：所有状态类字段必须绑定枚举，文档同步枚举说明，禁止口头约定
五、全局统一响应结构体（强制唯一）
所有接口强制使用该结构，无任何特例
{
  "code": 200,
  "msg": "success",
  "data": {},
  "timestamp": 0
}
1. 状态码唯一标准：200成功、400参数错误、401未登录、403无权限、404不存在、409冲突、500服务异常
2. 返回规则：msg简洁友好无堆栈，data无数据返回空结构，timestamp为毫秒时间戳
通用分页固定结构体（全局强制）
{
  "code": 200,
  "msg": "success",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "size": 10,
    "pages": 0
  },
  "timestamp": 0
}
六、异常统一处理规范
1. 全局统一拦截：禁止接口裸抛原生异常、堆栈信息对外暴露
2. 错误脱敏：内部报错、数据库错误统一友好提示，不泄露技术细节
3. 日志留痕：后台完整留存异常信息用于排查，对外完全脱敏
七、安全与文件传输规范
1. 接口分级权限：公开、登录、权限接口严格分层管控
2. 数据脱敏：手机号、证件、密钥、隐私信息返回强制脱敏
3. 请求防护：防重放、防重复提交、非法参数过滤
4. 日志安全：敏感参数禁止打印日志
5. 文件上传规范：校验后缀、MIME类型、大小，拦截非法可执行文件，返回统一文件信息结构
6. 文件下载规范：强制鉴权防越权，统一响应头防乱码，禁止暴露物理路径
八、限流熔断 & 版本兼容规范
1. 限流熔断：对外开放接口限流，核心接口熔断降级，异常统一标准报错，防服务雪崩
2. 迭代规则：只新增、不修改、不删除存量字段与路由，完全增量兼容
3. 接口废弃规则：旧接口废弃需标注、留过渡期，禁止直接下线
九、双AI自检与稽查标准
1. 开发AI自检项：路由、请求方式、传参规范、参数校验、返回结构、空值处理、枚举规范、超时配置、无硬编码、无语法报错
2. 稽核AI深度稽查项：接口逻辑、幂等性、边界容错、异常处理、安全合规、分页统一性、文件安全性、限流有效性、版本兼容性、可用性
3. 执行节点：单接口自动续跑，完整接口模块完工暂停 → 自检 → 稽核整改闭环 → 等待用户人工验收
十、终极固定执行流程（永久生效）
读取双规范 → 对齐接口标准 → 接口开发+参数校验+统一响应封装 → 逐项合规自检 → 模块完工全检 → 稽核AI深度审查整改闭环 → 暂停等待用户验收 → 验收通过进入下一模块。仅报错、阻塞、需求模糊时询问用户，其余场景全自动推进。
